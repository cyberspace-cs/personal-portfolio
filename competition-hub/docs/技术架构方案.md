# 技术架构方案

> 项目：竞赛雷达（Competition Radar）
> 角色视角：开发工程师
> 版本：v1.0

---

## 1. 架构总览（分层）

```
浏览器 (React SPA)
   │  HTTP / JSON, Bearer Token
   ▼
FastAPI 应用（API 网关 + 业务路由）
   ├─ 竞赛服务 competitions
   ├─ 分类服务 categories
   ├─ 认证服务 auth（Token 签发/校验）
   └─ 收藏服务 favorites
   │  原生 sqlite3 连接池（单连接/请求）
   ▼
SQLite 文件库（competition.db，WAL）
```

生产模式下 FastAPI 同时静态托管 `web/dist`（同源，SPA 深链回退），无需独立前端服务器。

---

## 2. 技术选型与理由

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 前端框架 | React 18 + TypeScript | 组件化、类型安全、生态成熟 |
| 构建 | Vite 6 | 秒级冷启、ESM 原生、零配置代理 |
| 样式 | Tailwind CSS 3.4 | 原子化、统一设计令牌、易做暗色赛博主题 |
| 路由 | react-router-dom 6 | 浏览器路由 + 深链 |
| 后端 | FastAPI | 异步、自动 OpenAPI、Pydantic 校验 |
| 数据访问 | 原生 sqlite3 | 零 ORM 依赖、轻量、与仓库既有 shuati-coach 同源架构，便于维护 |
| 认证 | Bearer Token + `auth_tokens` 表 | PBKDF2-SHA256 加盐，无第三方鉴权库 |
| 部署 | Uvicorn / Docker | 单进程即可承载 MVP 流量 |

**为什么不用 ORM**：MVP 数据模型简单、查询固定，原生 SQL 可读性高、零迁移工具负担；参数化查询已杜绝注入。

## 3. 模块划分（代码地图）

```
server/
  database.py   # 连接管理 + 建表（幂等）
  models.py     # Pydantic 请求/响应 Schema
  seed.py       # 示例数据（幂等）
  main.py       # 路由 + 依赖（get_current_user/require_user）+ 启动种子
web/src/
  lib/          # api.ts（请求封装）、auth.tsx（AuthContext）、ui.tsx（弹窗/Toast）、types.ts、format.ts
  components/   # Navbar/Footer/Hero/FilterBar/CompetitionCard/Pagination/AuthModal
  pages/        # HomePage/CompetitionDetail/FavoritesPage/SubmitPage/NotFound
```

关注点分离：API 客户端（lib/api.ts）与 UI 解耦；鉴权状态通过 Context 下发；UI 组件无业务逻辑。

---

## 4. 请求生命周期（以「收藏」为例）

```
前端点击收藏
  → lib/api.ts 注入 localStorage Token 到 Authorization
  → POST /api/favorites  {competition_id}
  → FastAPI 路由 require_user 依赖解析 Token → 查 auth_tokens 校验过期
  → 参数化 INSERT OR IGNORE favorites
  → 返回 {ok, favorited}
  → 前端本地更新卡片 is_favorited 状态（乐观更新，无需整列刷新）
```

---

## 5. API 设计原则

- **REST 风格**：资源命名复数（`/competitions`、`/categories`）；子资源用路径（`/favorites/{id}`）。
- **统一分页**：`?page=&page_size=`，响应含 `total/total_pages`。
- **统一错误**：失败返回 `{detail}`，配合 HTTP 状态码（400/401/404/409）。
- **幂等**：收藏 `INSERT OR IGNORE`；退出使 Token 失效。
- **最小权限**：写操作（竞赛 CRUD、收藏）均需 `require_user`；读操作匿名可用。

## 6. 安全设计（基线）

| 威胁 | 对策（已实现 / 待加固） |
| --- | --- |
| SQL 注入 | ✅ 全参数化查询 |
| 密码泄露 | ✅ PBKDF2-SHA256 加盐，不存明文 |
| 越权写 | ✅ Token 校验 + 过期检查 |
| CORS 滥用 | ⚠️ 当前 `allow_origins=["*"]` + `allow_credentials=True`（不合规）→ 待收紧 |
| XSS | ⚠️ Token 存 localStorage；React 默认转义文本，但需补安全响应头 |
| 暴力破解 | ⚠️ 认证接口无限流 → 待加限流 |
| 输入滥用 | ⚠️ 字段长度/枚举未强约束 → 待加校验 |

> 上述 ⚠️ 项为 Review 阶段重点，并在 Fix 阶段落实。

## 7. 部署架构

**模式 A（开发）**：前端 `npm run dev`（5173，代理 /api→8000）+ 后端 `uvicorn :8000`。

**模式 B（生产单体）**：`npm run build` → `uvicorn :8000` 同源托管 `web/dist`，前端与 API 同域，无跨域。

**模式 C（容器）**：多阶段 Dockerfile（node 构建 → python 运行），`docker compose` 一键起。

## 9. 关键决策记录（ADR）

- **ADR-1 原生 SQLite 而非 PostgreSQL**：MVP 单机部署，零运维；后续可按 `shuati-coach` 既有路径平滑切换。
- **ADR-2 Token 表而非 JWT**：避免签名密钥管理，便于「退出使单点失效」；30 天有效期。
- **ADR-3 后端同源托管前端**：降低部署复杂度，适合个人作品集场景。
