# 产品需求与功能设计文档（PRD）

> 项目：竞赛雷达（Competition Radar）· 技术竞赛聚合平台
> 角色视角：产品经理
> 版本：v1.0（对应已实现的 MVP）
> 参考：天天黑客松（heikesong.cn）、极客镇（jikezhen.com）

---

## 1. 产品背景与目标

### 1.1 背景
开发者与创作者在寻找技术竞赛（黑客松、Kaggle、算法赛、CTF、AI 大模型、创新创业等）时，信息分散在各大主办方官网、社群与公众号，缺乏一个统一、可筛选、可收藏的聚合入口。

### 1.2 产品目标
构建一个**聚合展示 + 检索筛选 + 个人收藏**的技术竞赛平台，让用户「在一个页面看见所有值得参加的比赛」，并支持贡献（发布）赛事信息。

### 1.3 成功指标（北极星）
- 竞赛覆盖品类 ≥ 6 类，单站可检索竞赛 ≥ 50 条（MVP 以示例数据验证）。
- 列表页首屏可筛选命中率 ≥ 90%（用户能在 3 次操作内找到目标竞赛）。
- 注册用户收藏转化率 ≥ 20%（浏览详情后点击收藏）。

## 2. 目标用户与用户故事

### 2.1 用户画像
| 角色 | 诉求 |
| --- | --- |
| 学生 / 算法爱好者 | 找 Kaggle、算法、CTF 练手，按时间/奖金排序 |
| 独立开发者 / 创客 | 找黑客松组队，关注线上/线下形式与城市 |
| AI 研究者 | 找大模型、Agent 主题赛事 |
| 创业者 | 找创新创业、路演类比赛与投资对接 |
| 内容贡献者 | 把自己知道的赛事发布出来 |

### 2.2 用户故事（User Stories）
- **US-1 浏览**：作为访客，我希望在首页看到竞赛卡片流，并能按分类/状态/形式筛选，以便快速浏览。
- **US-2 搜索**：作为访客，我希望输入关键词即可检索名称/主办方/标签，以便精准定位。
- **US-3 详情**：作为访客，我希望点开竞赛看到主办方、时间线、奖金、官网链接，以便决定是否报名。
- **US-4 收藏**：作为登录用户，我希望收藏竞赛并在「我的收藏」查看，以免错过报名截止。
- **US-5 认证**：作为用户，我希望注册/登录后能使用收藏与发布功能。
- **US-6 发布**：作为登录用户，我希望填写表单发布一场赛事，经校验后出现在列表。
- **US-7 管理**：作为登录用户，我希望能编辑/删除自己发布的赛事。

## 4. 功能详设（核心用例）

### 4.1 竞赛列表（US-1 / US-2）
- 输入：分类 slug、状态、形式、关键词 `q`、排序、页码。
- 处理：服务端参数化查询 + 分页（默认 12/页，上限 60）。
- 输出：卡片流（标题、分类、状态、城市、形式、奖金、标签、主办方、浏览量）+ 总数/总页。
- 边界：匿名可用；关键词模糊匹配标题/简介/主办方/描述/标签。

### 4.2 竞赛详情（US-3）
- 输入：竞赛 ID。
- 处理：返回完整字段；每次访问浏览量 +1；携带 Token 时返回 `is_favorited`。
- 输出：关键信息网格 + 描述段落 + 同类推荐（同分类 Top3）。

### 4.3 收藏（US-4）
- 前置：必须登录（未登录引导登录弹窗）。
- 接口：`POST /favorites`、`DELETE /favorites/{id}`、`GET /favorites`、`GET /favorites/check/{id}`。
- 约束：唯一 `(user_id, competition_id)`，重复收藏幂等。

### 4.4 认证（US-5）
- 注册：`POST /auth/register`，PBKDF2-SHA256 加盐哈希存储密码。
- 登录：`POST /auth/login`，返回 Bearer Token（有效期 30 天）。
- 退出：`POST /auth/logout` 使 Token 失效。

### 4.5 发布/管理（US-6 / US-7）
- 创建：`POST /competitions`（需登录），`slug` 唯一。
- 编辑：`PUT /competitions/{id}`（需登录）。
- 删除：`DELETE /competitions/{id}`（需登录）。

## 5. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 列表接口 P95 < 200ms（数据量 < 1k）；前端首屏 < 1.5s |
| 安全 | 参数化查询防 SQL 注入；密码加盐哈希；CORS 仅允许可信源；认证接口限流 |
| 可用 | API 可用性 ≥ 99.5%；前端响应式（移动/桌面） |
| 可维护 | 前后端分离、REST 风格、文档齐全（README/DB/API） |
| 部署 | 单体可跑（后端同托管前端），亦支持 Docker |

## 6. 验收标准（DoD）

- [ ] 6 类及以上竞赛可在首页聚合展示并筛选。
- [ ] 关键词搜索命中预期结果（如搜「Kaggle」能返回数据竞赛）。
- [ ] 未登录访问收藏/发布被拦截并引导登录。
- [ ] 注册 → 登录 → 收藏 → 取消收藏 全链路可用。
- [ ] 发布竞赛后出现于列表与详情，编辑/删除生效。
- [ ] 自动化测试覆盖核心接口且通过。
- [ ] 代码审查无「严重」级问题遗留。

---

## 7. 风险与假设

- 假设：示例数据用于演示，真实数据需接入主办方抓取/投稿审核（本期不含爬虫）。
- 风险：Token 存前端 localStorage 有 XSS 窃取风险 → 需在 Dev/Review 阶段以安全头与最小暴露面缓解。
- 风险：任何登录用户均可发布 → 生产需引入审核/角色（标注为后续迭代）。
