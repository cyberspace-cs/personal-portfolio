## 📱 产品简介（复赛版）

### 是什么
**「专属刷题教练」是一个纯Web端的多模型驱动智能备考平台**——单文件HTML即可打开，零注册零安装完全离线，兼容豆包/混元/智谱/Kimi/通义五大国产大模型，5个AI Agent协同组成你的24小时专属私教。解决备考人群「多APP切换混乱、错题分散、盲目刷题不知道刷什么、遇到不会的没人讲」四大核心痛点。

产品形态：单文件HTML网站（无需后端、无需部署，双击即开即用）

### 面向谁
**核心用户**：20-28岁备考人群——大学生考研、应届生考公/考编、在职人员考公/跳槽大厂、以及同时准备多类考试的「双线作战」人群。

**典型使用场景**：

| 用户 | 场景 | 产品如何解决 |
|------|------|-------------|
| 大三学生小王 | 考研408+秋招算法双线备考 | 一个页面切换考研/大厂题库，错题统一管理，AI教练告诉你「你概率统计弱，先刷这10道」 |
| 应届毕业生小李 | 国考省考事业单位巡考 | 错题自动归集到知识点，AI深度解析错题原因，生成针对性变式题巩固 |
| 在职备考小张 | 每天1小时30天冲刺省考 | AI规划师生成每日计划，告诉你「时间有限先刷高频考点+你薄弱的交集，性价比最高」 |

**完整用户使用路径**：
1. **打开**：双击HTML文件即用，零注册零等待
2. **选分类**：顶部选择考研/考公/大厂，开始刷题
3. **答题**：沉浸式答题，即时反馈，答题卡自由跳转
4. **错题**：答错自动入错题本，点击「问AI教练」获得深度解析
5. **对话**：和AI教练多轮对话，AI基于你的真实数据（RAG）给个性化建议
6. **规划**：让AI规划师根据你的时间和薄弱点生成学习计划
7. **巩固**：AI出题官给你生成针对性变式题强化薄弱点
8. **复盘**：看数据中心的雷达图/趋势图，AI复盘师给你周/月报告
9. **每日**：第二天打开直接看到今日推荐，不用再纠结刷什么

## 🛤️ 产品创作历程

### 灵感来源
最初的想法来自我自己备考时的真实痛苦：手机里装了5个APP，每天切换来切换去，错题分散在各个地方，想复习的时候不知道从哪开始。我想要的东西很简单：「一个地方放所有题，错题自动整理，告诉我今天该刷什么，不会的有人讲」。但市面上没有这样的产品，要么是垂直单一品类，要么是重APP要注册，要么是没有AI智能。

正好赶上TRAE大赛，我想：为什么不用AI做一个真正懂AI时代的刷题工具？

### 关键决策演进

**第一阶段（初赛Demo）：验证核心流程**
- 决策：先不碰AI，纯前端把刷题核心流程跑通
- 关键问题：单文件HTML还是多文件？→ 决策单文件，零依赖双击即开，极致轻量
- 结果：6道题的基础Demo，验证了刷题/分类/答题卡/页面切换核心交互

**第二阶段（复赛v2.0规划）：加入AI能力+升级UI**
- 决策1：AI Agent架构怎么设计？→ 不是做一个聊天框，而是5个Agent各司其职，模拟真实教练团队（主教练调度+解析师讲题+规划师做计划+出题官出题+复盘师复盘），这才是「教练」而不是「聊天机器人」
- 决策2：绑定一个模型还是支持多模型？→ 支持多模型兼容！用户自己填API Key，不绑定厂商，支持豆包/混元/智谱/Kimi/通义/任何OpenAI兼容API（包括本地Ollama），把选择权给用户
- 决策3：AI怎么懂用户？→ RAG三层检索：第一层你的个人错题数据，第二层知识点知识库，第三层题目上下文，让AI不是泛泛而谈，而是真的知道「你哪道题错了、错了几次、哪个知识点弱」
- 决策4：UI风格？→ 蓝白科技未来风，浅色深色双模式，科技感要适度，不能干扰长时间刷题阅读——刷题页保持干净舒适，对比度达到WCAG AAA标准
- 决策5：后端要不要？→ 坚决不要！纯前端单文件，所有数据存localStorage，隐私100%在用户本地，零部署成本，永远可用

### 遇到的问题与解决思路

| 问题 | 解决思路 |
|------|---------|
| 多Agent会不会太复杂单文件hold不住？ | 用MCP思想做轻量Agent调度，每个Agent是独立Prompt+工具集，主教练统一调度，架构清晰不臃肿 |
| RAG向量检索在浏览器端能跑吗？ | V1先做结构化数据注入+标签匹配保证效果，V2再用Transformers.js+bge-small-zh上本地向量检索，渐进式实现 |
| 多模型API格式不统一怎么办？ | Model Hub适配层统一封装成OpenAI格式，不同厂商写适配器，新增模型只加配置 |
| AI幻觉胡说八道怎么办？ | Harness多层评测：事实性检查+相关性检查+用户反馈闭环，不对就重新生成，兜底不说胡话 |
| 单文件HTML代码难维护？ | 严格模块化，小步快跑每轮只改一个点，改完浏览器验证 |

## 🔧 技术方案

### 技术栈

| 层 | 技术选型 | 选型理由 |
|----|---------|---------|
| **前端架构** | 原生 HTML5 + CSS3 + Vanilla JS（单文件） | 零构建零依赖，双击即开，永久可用 |
| **UI样式** | 原生CSS + CSS变量 + backdrop-filter | 不引入框架，CSS变量实现深浅色一行切换 |
| **图表** | Chart.js (CDN引入) | 轻量成熟，图表类型全 |
| **AI大模型** | Fetch API + OpenAI兼容格式 + SSE流式 | 无需SDK，直接调用API，流式响应体验好 |
| **数据存储** | localStorage | 纯本地，隐私安全，浏览器原生支持 |
| **响应式** | CSS Flex + Grid + media query | 原生实现 |
| **动画** | CSS transition/animation | 轻量流畅 |

### 关键实现思路

**1. 主题切换**：CSS Variables统一管理颜色，切换给`<html>`加`data-theme="dark"`，偏好存localStorage，0.3s过渡平滑。

**2. 多Agent调度**：每个Agent是独立配置（systemPrompt+tools+modelPreference），主教练根据意图handoff给对应Agent。

**3. RAG实现**：用户答题实时更新用户画像（错题/正确率/统计），发消息前把相关数据注入System Prompt，V1结构化注入，V2再加向量检索。

**4. 多模型兼容**：Model Hub适配层统一封装成OpenAI格式，不同厂商写适配器，新增模型只加配置。

**5. 数据持久化**：每次操作debounce存localStorage，不可用时降级内存模式并提示。
