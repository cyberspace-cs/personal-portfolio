## 二、产品简介（复赛版 · 完整成品）

**是什么**：一个 **微信小程序 + H5 双形态**的备考平台，把考研、考公、大厂笔面试等分散在多平台的题库、错题、
学习数据统一聚合到一个入口，用"手机开刷 → 错题归集 → 数据量化 → 智能推荐 → 模拟考"的完整闭环，
把通勤、排队、睡前的碎片时间，变成系统化备考。

**面向谁**：
- 考研党（数学 / 英语 / 政治 / 专业课）
- 考公党（行测 / 申论 / 公基）
- 大厂预备役（算法 / 八股 / 系统设计，校招 & 社招）

**典型场景**：日常刷题、考前冲刺、笔面模拟、错题回顾与针对性强化。

### 完整功能清单（用户使用路径）

| 模块 | 核心能力 |
|------|----------|
| **首页** | 多源聚合状态展示、痛点呈现、一键进入各功能 |
| **智能刷题（小程序原生）** | 微信小程序内原生答题流：多平台题库聚合（**60 道种子题，考研/考公/大厂各 20 道**）、单选/多选/判断多题型、分类筛选、即时解析、答题进度、答错自动入错题本 |
| **跨平台错题本** | **答错自动归集**、按知识点聚合、**艾宾浩斯遗忘曲线**智能排期复盘、待复盘提醒、重做消化 |
| **数据中心** | 基于真实答题记录**动态计算**：累计刷题、正确率、错题数、连续打卡；趋势图 + 掌握度雷达 + 平台占比饼图 |
| **智能推荐** | 根据掌握度**动态生成**个性化学习路径 + 今日推荐题 + 目标完成度 |
| **AI 智能讲题** | 答错后一键 AI 讲题（结构化拆解步骤 + 避坑技巧），并**现场生成 3 道同考点变式题**巩固 |
| **考前押题报告** | 聚合全量刷题/错题数据，AI 生成冲刺押题方向、复习计划与得分预测（留存钩子） |
| **全真模拟考** | 按考试结构组卷、**限时倒计时**、自动评分、逐题解析、错题自动入本 |
| **体验** | 微信小程序原生交互 + H5 深度版（web-view 承载）；**登录后数据写入服务端 SQLite 云端同步**，多端续刷；**全站统一 SVG 描边图标**，跨平台渲染一致 |

**使用路径示例**：首页 → 开始刷题（答错自动进错题本）→ 数据中心看到掌握度雷达 → 智能推荐给出"先攻克概率统计"→ 去错题本按遗忘曲线复盘 → 模拟考检验 → 数据实时更新。

## 四、产品创作历程

1. **灵感来源**：亲历备考时"多平台切换 + 错题割裂"的痛苦，萌生"一站式聚合"的想法。

3. **复赛演进**：确立"闭环"这一核心——刷题产生数据，数据驱动错题、图表与推荐，形成正反馈。
   - 关键难点：错题的"智能复盘"如何做？→ 引入**艾宾浩斯遗忘曲线**，用分阶段 nextDue 排期，答对升阶、答错降阶。
   - 关键决策：坚持**单文件 + 本地持久化**，让评审无需部署即可打开体验，同时数据不丢。

## 五、技术架构与后端接入（Python + FastAPI + SQLite）

复赛在保留"单文件前端 + 本地兜底"易用性的同时，引入 **Python 后端**完成全量数据接入，形成真实可用的产品闭环：

### 5.1 架构总览

```
┌──────────────┐      HTTP / JSON       ┌─────────────────────────┐
│  前端 (coach.html) │ ◄──────────────► │  Python + FastAPI 后端    │
│  原生 JS + Chart.js │   fetch /api/*    │  (单进程，托管前端静态页)  │
└──────┬───────┘                      └───────────┬─────────────┘
       │ 未登录：仅写 localStorage                 │ 登录后：写入 SQLite
       ▼                                          ▼
  本地兜底（离线可用）                      SQLite（coach.db）
                                           users / questions / quiz_records
                                           wrong_book / daily_streaks / exam_records
```

### 5.2 核心设计决策

- **登录即云同步**：前端新增登录/注册，登录态用 `sessionStorage` 持有 `user_id`；未登录仍可刷题（仅本地），登录后刷题/错题/打卡/模考记录**双写**（本地 + 服务端 SQLite），刷新不丢、多端可续。
- **题库服务端化**：启动优先从 `/api/questions` 拉取（后端已 seed **60 道**多学科题库，考研/考公/大厂各 20 道，含难度分级），失败回退内嵌数组，保证离线可演示。
- **小程序 + H5 双形态（B+C 方案）**：核心刷题流（首页/答题/错题本/打卡）用微信小程序原生 WXML/WXSS 实现，手机端体验最佳；AI 讲题、变式题、押题报告等重交互页面用 `web-view` 承载完整 H5 平台（`coach.html`）。小程序通过 `wx.request` 直接复用同一套 FastAPI 后端 `/api/*`，数据完全一致。
- **AI 能力真正嵌入使用链路**（对应评分"TRAE 能力运用"）：答错 → 弹层调用 `/api/explain` 智能讲题 → 调用 `/api/gen` 现场生成 3 道同考点变式题；"押题报告"页调用 `/api/report` 生成 AI 冲刺建议。
- **密钥安全**：大模型 API Key 仅存于服务端环境变量，前端永不接触；**无 Key 时自动降级**为结构化讲解，功能不中断，复赛演示零依赖。

### 5.3 后端接口一览

| 接口 | 作用 |
|------|------|
| `POST /api/login` · `/api/register` | 用户登录 / 注册 |
| `GET /api/questions` | 拉取服务端题库（按分类筛选） |
| `POST /api/quiz/record` · `GET /api/quiz/history/{uid}` | 刷题记录写入 / 读取 |
| `POST /api/wrong-book` · `GET /api/wrong-book/{uid}` | 错题归集 / 读取 |
| `POST /api/checkin/{uid}` · `GET /api/streak/{uid}` | 打卡 / 连续天数 |
| `POST /api/exam/record` · `GET /api/exam/records/{uid}` | 模考记录写入 / 读取 |
| `GET /api/mastery/{uid}` | 按错题动态计算知识点掌握度 |
| `POST /api/explain` · `/api/gen` · `/api/report` | **AI 讲题 / 变式题 / 押题报告** |

## 七、加分项

- **技术栈**：前端原生 HTML + CSS + JavaScript + Chart.js；后端 **Python + FastAPI + SQLite**，单进程同时托管前端与 API，`API_KEY` 仅服务端持有，无 Key 自动降级。
- **关键实现**：艾宾浩斯遗忘曲线复盘算法、答题数据实时聚合计算、掌握度雷达动态生成、限时模拟考评分引擎、**登录后云端多端同步的双写兜底机制**。
- **TRAE 能力嵌入**：AI 讲题、同考点变式题生成、考前押题报告已嵌入真实使用链路（答错→讲题→变式题→押题报告），而非孤立演示。
- **商业价值**：面向庞大备考群体，可通过高级会员（智能学习路径规划、深度数据分析、AI 深度讲题）与题库合作分成变现。
- **社会价值**：降低备考信息过载成本，让复习更系统、更公平。
- **迭代规划**：接入真实题库 API、组队 PK、学习社区、小程序上架与消息推送。
