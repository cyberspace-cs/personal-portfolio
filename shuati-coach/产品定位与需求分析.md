# 专属刷题教练 · 产品定位与需求分析

> 用途：支撑 TRAE AI 创造力大赛复赛评分（产品完成度 / 技术实现 / 实用性 / 创新性）
> 一句话定位：**别的 App 让你按章节盲刷、自己整理错题；我们让你的每一次答题都在重算真实薄弱度，自动建错题本、自动排复习、自动推你最该刷的下一题。**

---

## 1. 目标用户精准定位

### 结论：主打「考研 / 考公 / 教资等硬考试备考党」，四六级/大厂笔试作为泛流量入口。

| 候选用户群 | 是否核心 | 选择理由 |
|---|---|---|
| **考研/考公/教资硬考试党** | ✅ **核心** | 周期长（6~12个月）、题量大（5000+）、决策焦虑最重，对"该刷什么"的智能决策付费意愿最强；错题长期积累形成沉没成本，留存天然强。 |
| 大厂/国企笔试面试党（算法+行测） | ◻ 次要入口 | 周期短、密度高、需求急，适合做"轻量引流"，但一次性使用倾向明显，留存弱。 |
| 在校生（期末/四六级） | ◻ 泛流量 | 基数大但焦虑弱、付费弱，用于扩大用户规模（对应社会服务赛道"受众规模"）。 |

**为什么选硬考试党（对齐评分点）**：
- **场景成熟（实用性）**：需求真实、高频、目标人群清晰具体（大三下~大四、二战、在职考公）。
- **持续使用价值（实用性）**：备考周期长 = 天然高频回访；错题库越用越厚 = 迁移成本高。
- **需求创新（创新性）**：这类人痛在"信息过载下不知道该学哪"，是长期存在但未被有效解决的决策类需求。

## 2. 用户痛点与现有工具分析

### 2.1 现有工具及特点

| 工具 | 类型 | 特点 / 局限 |
|---|---|---|
| 粉笔、考研帮、中公 | 垂直题库 App | 题量大，但按**章节推荐**（非按个人薄弱度），错题本要手动整理，跨科目数据割裂 |
| Anki | 记忆卡片 | 有间隔复习算法，但**要自己造卡**，门槛高、无题库、无数据分析 |
| Excel / 纸质错题本 | 手工记录 | 灵活但**无法自动排复习、无法量化薄弱点**，越记越乱 |
| LeetCode / 牛客 | 编程刷题 | 面向大厂，与考研/考公数据完全隔离 |

**核心问题：用户被迫在 3~5 个工具间横跳，数据割裂，没有一个入口能回答"我到底薄在哪、该刷什么、复习到哪了"。**

### 2.2 主要痛点（四类，逐一对应产品能力）

| 痛点 | 具体表现 | 产品对应能力 |
|---|---|---|
| **① 知识记忆与复习规划** | 刷了就忘，凭感觉复习，考前发现旧知识漏一片 | 艾宾浩斯遗忘曲线自动排期（EBB=[0,1,2,4,7,15]），每天首页推"今日该复习的旧错题" |
| **② 错题管理与查找** | 错题散落多 App/Excel，无法拼出完整错题集 | 答错**自动归集**统一错题本，按考点/掌握度分层，永久存档 |
| **③ 薄弱点识别** | 70% 时间在刷已会的，真正弱项从未被定位 | 每次答题重算真实薄弱度，数据中心雷达图把"最弱 2 模块"钉在首页 |
| **④ 动力与反馈缺失** | 一个人备考，无正反馈，中途放弃 | 连续打卡 streak + 每日复习任务游戏化 + 阶段性数据"变绿"正反馈 |

## 3. "智能"核心卖点定义（优先级）

| 优先级 | 智能功能 | 定位 | 为什么这个优先级 |
|---|---|---|---|
| **P0** | **智能薄弱度推荐**（该刷什么） | 决策替代，主卖点 | 用户最买单；是与粉笔/Anki 的核心差异（决策 > 效率） |
| **P0** | **智能错题管理与复习规划** | 效率闭环，护城河 | 数据沉淀基础，越用越准，构成留存与推荐的数据源 |
| **P1** | **智能题目解析（AI 讲题 + AI 生成相似题）** | 技术创新，TRAE 嵌入链路 | 答错→AI 讲这道→现场生成 3 道同考点变式，把 TRAE 大模型能力真正嵌入使用链路（对齐"技术创新"评分） |

**差异化一句话（写进创新性板块）**：
> 市面产品让你"按章节自己刷、自己整理错题"；我们把"我该刷什么"这个决策交给系统——**每一次答题都在重算你的真实薄弱度**，自动建错题本、自动排复习、自动推下一题，答错还能让 AI 当场讲懂并生成变式题巩固。

## 4. 典型用户痛点场景（前后对比 + 量化效果）

### 场景一：保研失败转考公，3 个月上岸
- **背景**：大四林同学保研失败，9 月才决定考公，只剩 3 个月，行测底子薄、焦虑严重。
- **用前**：每天刷 100+ 题全凭感觉，70% 在刷已会的，资料分析始终没提上来。
- **用后**：每天打开先做"系统推的 15 道弱项新题 + 37 道到期旧错"；数据中心显示行测 5 模块逐周变绿。
- **效果**：**3 个月行测从 55 分提到 72 分，成功上岸。**

### 场景二：二战考研，靠错题地图止住崩溃
- **背景**：王姐二战，一个人备考到第 3 个月濒临放弃。
- **用前**：错题记在 3 个 App + Excel，复盘拼不全，看不到进步，动力枯竭。
- **用后**：所有错题自动归集成"错题地图"，streak 打卡 + 每日复习任务给正反馈。
- **效果**：**坚持完整周期，政治选择题正确率从 60% 提到 88%。**

### 场景三：大厂笔试急救，一周补齐八股弱项
- **背景**：应届生小陈两天后大厂笔试，八股知识点零散。
- **用前**：面经太多无从下手，不知道哪块最容易被考挂。
- **用后**：模拟考场限时组卷 → 数据中心定位最弱 2 类 → AI 现场生成变式题猛攻。
- **效果**：**笔试通过率显著提升，进入面试环节。**

### 场景四：在职考研，碎片时间高效复习
- **背景**：在职考研，每天只有通勤 40 分钟。
- **用前**：碎片时间不知道刷什么，效率低。
- **用后**：移动端打开即见"今日必复习清单"，40 分钟精准打薄弱点。
- **效果**：**用一半时间达到原来的复习覆盖度。**

### 场景五：教资考生，理论题记不住
- **背景**：教资综合素质大量理论记忆点。
- **用前**：死记硬背，考前遗忘严重。
- **用后**：艾宾浩斯排期 + AI 讲题把抽象理论讲成大白话。
- **效果**：**记忆点留存率大幅提升，一次通过。**

## 5. 技术架构可行性分析

### 5.1 当前形态（复赛完成度基础）
- 单文件 HTML + 原生 JS + Chart.js，localStorage 持久化。
- 优点：零部署、双击即用、演示稳定，直接支撑"产品完成度"（核心流程可顺畅走通、无严重 bug）。

### 5.2 是否需要后端
| 能力 | 是否需要后端 | 说明 |
|---|---|---|
| 刷题 / 错题归集 / 数据统计 / 图表 | ❌ 前端即可 | localStorage 已闭环，保证 Demo 稳定 |
| **AI 讲题 / AI 生成相似题** | ✅ 需要 | 调用大模型 API，密钥不能暴露在前端，需轻量后端代理 |
| 错题云存档 / 押题报告 / 跨设备同步 | ✅ 需要 | 需账号体系 + 数据库 |

### 5.3 推荐架构（渐进式，保证完成度同时拉技术分）
```
[前端 SPA (现有 coach.html 升级)]
        │
        ├── 本地：localStorage（离线可用，保证核心流程稳定）
        │
        └── 轻量后端 (Node/Serverless 云函数)
                ├── /api/explain   → 调用大模型讲题（TRAE 能力嵌入链路）
                ├── /api/generate  → 生成同考点变式题
                └── /api/report    → 生成考前押题报告
                        │
                        └── 数据存储：Serverless DB / KV（错题云存档）
```

**架构要点（对齐"技术方案完整、架构合理"评分）**：
- **离线优先**：核心刷题闭环不依赖网络，演示永远稳定 → 保完成度。
- **AI 走后端代理**：保护密钥、可控成本、可加缓存 → 技术方案完整。
- **渐进增强**：无网 = 静态题库正常用；有网 = AI 讲题/变式题/云同步增强 → 兼顾稳定与创新。

### 5.4 数据存储方案
| 数据 | 方案 |
|---|---|
| 答题记录 / 错题 / streak | 本地 localStorage（离线）+ 云端 KV（登录后同步） |
| 题库 | 内置静态 JSON + AI 动态生成扩充 |
| AI 讲题缓存 | 后端按题目 hash 缓存，降本提速 |
