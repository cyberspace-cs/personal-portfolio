## 4. 架构合理性

- **主题系统零侵入**：仅新增变量集与少量 JS，未改动任何具体样式规则，符合「最小改动」原则，回归风险极低。
- **数据库升级向后兼容**：`init_db()` 用 `IF NOT EXISTS`，老库升级只追加；升级路径经 `DB_DIR` 环境变量集中，PG 迁移仅留接口（本期不切，符合方案）。
- **题库即数据资产**：版本/校验和/来源元信息随 JSON 落盘并在 `meta` 接口暴露，便于审计与回滚。
- **自动化就绪**：`update_bank.py` 无状态、幂等（基于 stem 去重保 id 稳定），可直接被 cron/平台自动化周期调用。

## 6. 发现项清单（Findings）

| ID | 严重度 | 维度 | 描述 | 建议 |
|---|---|---|---|---|
| F-1 | 低 | 安全/健壮 | `/api/study-plan/save` 信任客户端 `user_id`，传入不存在的 id 会触发外键违例导致 500。与全站既有端点行为一致，但可更友好。 | 保存前校验用户存在，缺失则返回 400；或捕获 IntegrityError 转 400。（迭代阶段处理） |
| F-2 | 低 | 安全 | `CORS *` 在公网暴露时过宽（既有问题，非本期引入）。 | 部署侧收紧为前端域名；本期不阻塞。 |
| F-3 | 提示 | 设计 | `update_bank.py` 默认将版本置 `published`；若希望「生成候选→人工评审→发布」两阶段，可先 `draft` 再由独立步骤 `publish`。 | 当前直接发布便于自动化演示，可接受；若评审流程要求严格，后续加发布步骤。 |
| F-4 | 提示 | 兼容 | 深色变量未覆盖极个别内联 `#fff` 文本（如品牌按钮白字），在深色下仍可读，无需处理。 | 无需改动。 |
