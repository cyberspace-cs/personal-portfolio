## 2. 整体产品设计

### 2.1 产品定位
> 一站式打通**考研 · 考公 · 大厂笔面**三大题库的"多源数据聚合智能备考平台"。
> 解决考生在多平台反复切换、数据割裂、错题无法统一管理、缺乏个性化路径的痛点。

### 2.2 核心功能矩阵
| 模块 | 能力 | 匿名（体验模式） | 登录后（解锁更多） |
|---|---|---|---|
| 首页 | 题库规模展示、入口导航 | ✅ 看得到覆盖题数 | ✅ 个人正确率/打卡 |
| 刷题 | 按分类练习、即时判分、解析 | ✅ 可刷、可判分 | ✅ 错题自动入书、打卡 |
| 考场 | 模拟考试、计时、知识点分布 | ✅ 可做、出分 | ✅ 成绩存档、趋势 |
| 数据中心 | 趋势/掌握度/分类图、错题本、薄弱点 | ✅ 看题库聚合示例图 | ✅ 个人真实数据画像 |
| 智能推荐 | 薄弱点学习路径 + 推荐题 | ✅ 看基于题库的示例推荐 | ✅ 基于个人错题的定制推荐 |
| 押题报告 | 冲刺报告 | ✅ 看示例报告（标注非个人数据） | ✅ 基于真实数据的专属报告 |
| AI 助手 | 多 Agent 答疑/解析 | ⚠️ 受后端 LLM 开关影响 | ✅ 个性化上下文 |

### 2.3 关键设计原则（本次版本确立）
**默认开放、登录增值。**
- 访客（匿名）能浏览全部 demo 与展示性功能，先"看到价值"再转化。
- 登录解锁的是**个人持久化能力**：刷题记录保存、错题本、连续打卡、个性化推荐、专属押题报告、AI 个性化解析。
- 实现机制：前端 `checkLoginRequired` 不再硬拦截；`user_id` 在后端为可空，匿名请求走 `demo` 分支（不落库或仅展示聚合数据）。

### 2.4 用户旅程
```
访客 → 首页看到题库规模 → 体验刷题/考场/数据中心(示例)/推荐(示例)/报告(示例)
     → 底部"体验模式"提示条引导登录
     → 登录/注册 → 同上模块切换为「个人真实数据」+ 错题本/打卡/个性化
```

## 3. 数据库设计

### 3.1 现状：SQLite（MVP / 本地开发）
6 张表，源码见 `server/database.py`：

```sql
questions(id, cat, src, type, stem, opts(JSON), answer(JSON), explain, topic, difficulty)
users(id, username UNIQUE, password_hash, created_at)
quiz_records(id, user_id, cat, total, correct, created_at)
wrong_book(id, user_id, question_id, error_count, last_error_at, UNIQUE(user_id,question_id))
daily_streaks(id, user_id, check_date, created_at, UNIQUE(user_id,check_date))
exam_records(id, user_id, exam_type, total, correct, duration, time_used, created_at)
```
- `opts`/`answer` 以 JSON 文本存储（便于多选项/多选/判断）。
- 索引：`questions(cat)`、`*_records(user_id)`、`wrong_book(user_id)` 等。
- 鉴权：SHA-256 无盐密码哈希，**无 token/session**（前端用 `sessionStorage` 存 `user_id`）。

> 现状够用但存在生产短板：单文件并发弱、无水平扩展、无缓存层、密码无盐、无令牌过期。

### 3.2 演进方案（生产推荐）

#### 方案 A（推荐）：PostgreSQL 主库 + Redis 辅助
**选型理由**：prod-ai 同生态的 Postgres 易获得；ACID 稳定；`JSONB` 天然适合题库 `opts/answer/meta`；索引/分区成熟；配合 Redis 解决高并发与缓存。

```sql
-- 题库：用 JSONB 存放可变结构，便于"题库完善"时扩展字段而不改表
CREATE TABLE questions (
  id            BIGSERIAL PRIMARY KEY,
  cat           TEXT NOT NULL,
  src           TEXT NOT NULL,
  type          TEXT NOT NULL,
  stem          TEXT NOT NULL,
  opts          JSONB NOT NULL,
  answer        JSONB NOT NULL,
  explain       TEXT DEFAULT '',
  topic         TEXT NOT NULL,
  difficulty    TEXT NOT NULL DEFAULT 'medium',
  meta          JSONB DEFAULT '{}',   -- 来源链接、年份、标签等
  created_at    TIMESTAMPTZ DEFAULT now()
);
CREATE INDEX idx_q_cat ON questions(cat);
CREATE INDEX idx_q_topic ON questions(topic);

-- 用户：密码加盐（bcrypt/argon2），增加令牌与过期
CREATE TABLE users (
  id            BIGSERIAL PRIMARY KEY,
  username      TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  created_at    TIMESTAMPTZ DEFAULT now()
);
CREATE TABLE user_tokens (            -- 登录态（也可放 Redis）
  user_id       BIGINT REFERENCES users(id),
  token         TEXT PRIMARY KEY,
  expires_at    TIMESTAMPTZ NOT NULL
);
-- quiz_records / wrong_book / daily_streaks / exam_records 同结构，user_id 改 BIGINT + 索引
```

**Redis 用途（key 设计）**
| 用途 | Key 示例 | 说明 |
|---|---|---|
| 会话/令牌 | `sess:{token}` → user_id（TTL 7d） | 替代无状态明文 user_id |
| 题库聚合缓存 | `meta:questions` | `/api/questions/meta` 结果，5 min 过期 |
| 热门/推荐 | `rec:hot:{cat}` | 高频推荐结果缓存 |
| 连续打卡 | `streak:{user_id}` | 计数器（TTL 到次日） |
| 限流 | `ratelimit:{ip}:/api/chat` | AI 接口防刷 |
| AI 流式缓冲 | `chat:stream:{cid}` | 多 Agent 流式输出缓存 |

#### 方案 B：MySQL（若团队更熟）
- 与 Postgres 同为主关系型，表结构几乎一致；`JSON` 列也可存 `opts/answer`（5.7+ 支持）。
- 差异：Postgres 的 `JSONB` 索引/查询更强，分区与扩展生态更优；MySQL 运维资料更多。**二者皆可**，按团队偏好选。

#### 方案 C：引入 NoSQL（MongoDB）存非结构化
- **适合**：题库文档（字段灵活、版本多）、AI 对话历史、Agent 轨迹日志、埋点。
- **不建议**作主业务库：刷题记录/错题本/打卡需要强一致事务与关联查询，关系型更稳。
- 折中：Postgres 主库 + MongoDB 存聊天/日志类半结构数据（可选）。

> 结论：**主库 PostgreSQL + Redis 缓存/会话** 是当前最优解；MySQL 为等价替代；NoSQL 仅作为非结构化数据补充，不替代主库。

### 3.3 本次版本对数据层的改动
1. 题库外置为 `data/questions.json`（86 题），`seed_questions()` 优先读 JSON、回退硬编码，便于"题库完善"。
2. `models.py` 中 `user_id` 改为可选，新增 `QuizCheckIn`/`QuizCheckItem`：支持**匿名判分**（`/api/quiz/check` 不落库）。
3. 新增公开接口 `/api/questions/meta`：返回题库聚合（total/分类/类型/来源/难度/知识点），供体验模式展示。
4. 刷题/错题/考试记录接口在 `user_id=None` 时走 demo 分支（返回 `{"ok":true,"demo":true}`），不写库。

## 4. 前后端设计

### 4.1 前端
- **coach.html（Web SPA）**：原生 JS + Chart.js，单文件多视图（`.view` + `.tabs` 切换）。
  - 体验模式改造点（本次版本）：
    - `checkLoginRequired()`：去掉硬拦截，改为始终进入视图并调用 `updateDemoBanner()`。
    - `updateHomeStats()`：匿名时展示题库覆盖题数（`/api/questions/meta` 的 `total`），个人指标显示"体验"。
    - `initCharts()`：匿名时调用 `renderDemoCharts()`，用题库聚合数据渲染趋势/掌握度/分类图，错题本/薄弱点提示"登录后保存"。
    - `initRecommendation()`：匿名时展示基于题库高难题的示例推荐。
    - `genReportBtn`：匿名时生成"体验版示例报告"（明确标注非个人数据）。
    - 底部固定"体验模式"提示条，点击引导登录。
  - API 封装：`apiFetch()`；持久化接口（`apiGet*`）在未登录时直接返回空，不报错。
- **miniprogram/**：`app.js` 的 `ensureUser()` 自动注册匿名 `wx_*` 用户，无登录门槛。
- **agent.html**：对接 `/api/chat`（Hermes Agent / 多 LLM 提供商兜底）。

### 4.2 后端（FastAPI）
- 分层：`main.py`（路由）+ `models.py`（校验）+ `database.py`（连接）+ `agent/`（多 Agent 编排，含 MCP 工具 `exam_syllabus`/`question_bank_search`）。
- 鉴权/体验模式：
  - 登录：`/api/register`、`/api/login`（SHA-256，返回 `user_id`）。
  - 匿名：`user_id` 可空，相关接口返回 demo 结果或跳过落库。
- 关键 API 清单：
  | 方法 | 路径 | 说明 | 登录 |
  |---|---|---|---|
  | GET | `/api/health` | 健康检查（含 ai/hermes 状态） | 否 |
  | GET | `/api/questions?cat=` | 题库列表 | 否 |
  | GET | `/api/questions/meta` | 题库聚合（公开展示） | 否 |
  | POST | `/api/quiz/check` | 匿名判分（不落库） | 否 |
  | POST | `/api/quiz/record` | 刷题记录 | 是（空则跳过） |
  | POST | `/api/wrong-book` | 错题入书 | 是 |
  | GET | `/api/wrong-book/{uid}` | 错题本 | 是 |
  | POST | `/api/checkin/{uid}` | 打卡 | 是 |
  | GET | `/api/streak/{uid}` | 连续打卡 | 是 |
  | POST | `/api/exam/record` | 考试成绩 | 是 |
  | GET | `/api/mastery/{uid}` | 知识点掌握度 | 是 |
  | POST | `/api/chat` | AI 助手（Hermes/多 LLM） | 受开关 |
- 部署：`deploy/` 提供 Docker + Hermes + nginx，`main` 分支推送到 prod-ai 自动构建。

### 4.3 已知问题与已修复（v2 收尾）
- ~~`/api/questions/meta` 被 `/api/questions/{question_id}`（int）路由遮蔽 → 422~~ → **已修复**：将 `meta` 路由前置。
- ~~`/api/explain` 422（前端发 `question_id`）~~ → **经验证原可用**：前端发 `{question:{...}}` 对象，与后端 `ExplainIn.question: QuestionPayload` 一致，无需修改。
- ~~密码无盐 SHA-256~~ → **已改为加盐 SHA-256**（`salt$hash`），`verify_password` 兼容旧无盐哈希；登录走 `verify_password` 校验。
- ~~`coach.html` 的 `API_BASE` 写死 `localhost`~~ → **已改为智能判断**：本地（file://、localhost、127.0.0.1）走 `http://localhost:8000/api`；生产（http/https 域名，如 `taoxie.vip`）走同域 `/api`（由 nginx 反代）。
- **仍待做（v3+）**：JWT / Redis 令牌与过期、PostgreSQL 主库 + Redis 缓存（见 3.2）；个性化推荐深化（v5）。

## 5. 用户痛点与产品映射

| 用户痛点 | 产品解法 |
|---|---|
| 考研/考公/大厂题库分散在多个 App，反复切换 | 多源聚合一页管理（cat: 考研/考公/大厂） |
| 错题散落各平台，无法统一复盘 | 跨源错题本 `wrong_book` + 薄弱点分析 |
| 不知道自己薄弱在哪、该刷什么 | 数据中心掌握度雷达 + 智能推荐学习路径 |
| 刷题没规划、难坚持 | 连续打卡 `daily_streaks` + 押题报告冲刺计划 |
| 考前想押重点没依据 | 基于真实数据的押题报告（登录后专属） |
| 新用户怕注册麻烦、看不到价值就走 | **体验模式**：先免登录看 demo/展示，再转化 |
