## 1. 方向一：浅色 / 深色模式（主题系统）

### 1.1 设计策略（暗色默认 + 变量层覆盖）
- 以「原分支」`public/shuati-coach.html` 视觉基线为准：其采用**暗色默认**，`:root` 即暗色变量集，仅用 `:root[data-theme="light"]` 一层覆盖变量实现浅色；不改动任何具体样式规则，零回归风险。
- 主题状态存 `localStorage.theme`，缺省值为 `'dark'`（首屏即暗色，契合科技感定位）；`<head>` 内联脚本在解析 CSS 前执行，杜绝 FOUC 闪烁。

### 1.2 双态切换
- 枚举 `{dark, light}`，状态存 `localStorage.theme`。
- 导航栏提供 `.theme-toggle` 日/月图标按钮，点击在 `dark ↔ light` 间循环，图标与 `title` 同步（🌙/☀️）。

### 1.3 图表主题适配（关键细节点）
- `renderDemoCharts()`（匿名体验模式的演示图表）与 `initCharts()` 采用与暗色主题一致的硬编码配色：`ink = '#9aa6c8', grid = 'rgba(255,255,255,.07)'`，确保暗色默认下图表清晰可读、无浅色硬背景。
- 主题切换时若当前视图为「数据中心」，重新调用 `initCharts()`（内部 `destroyCharts()` 后重建），已渲染图表即时变色。

### 1.4 新增/修改点
- `coach.html` / `public/shuati-coach.html`：沿用 `:root[data-theme="light"]` 覆盖层 + `.theme-toggle` 按钮；新增 JS `applyTheme/initTheme`；演示图表配色与暗色主题对齐；并叠加「学习计划 / 体验模式 / 题库元信息」三大功能（见下文方向二~四）。

## 2. 方向二：题库自动化长期更新

### 2.1 题库即版本化数据资产
- `questions.json` 元信息增强：`{version, generated_at, count, sources, checksum, questions}`（`sources`=来源计数，`checksum`=题库内容 SHA-256）。
- **增量生成**：`gen_questions.py` 读取现有 `questions.json`，合并 `EXTRA/NEW` 增量池（按 `stem` 去重），保留既有顺序（DB 侧以 `stem` 为幂等键保证 `id` 稳定），追加新题。

### 2.2 版本表与流水
- `database.py` 新增 `question_bank_versions(version, count, sources_json, summary, status, created_at, checksum)`。
- `update_bank.py`（新增，自动化入口）：
  1. 调 `gen_questions.py` 逻辑生成最新 JSON（含校验）；
  2. 计算 checksum；
  3. 插入一条 `status='draft'` 版本记录；
  4. 校验通过（无越界/重复/空知识点）后置 `published`；
  5. 失败则非零退出，阻断后续入库。
- `/api/questions/meta` 在原有统计基础上，额外返回 `version / generated_at / sources / checksum`（从 JSON 文件读取），前端可展示「题库版本」。

### 2.3 长期自动化规划（执行侧）
- 通过平台「自动化」能力或 `cron` 周期性执行 `update_bank.py`：
  - 每周：生成候选 `draft` + 校验报告；
  - 每月：评审并将通过的候选 `publish`。
- 本期实现脚本与接口能力，自动化调度在部署侧配置（测试阶段用一次性触发验证全链路）。

### 2.4 新增/修改点
- `server/gen_questions.py`：增量模式 + 元信息增强 + 校验器。
- `server/update_bank.py`（新增）：生成→校验→版本落库流水线。
- `server/database.py`：`question_bank_versions` 表 + 索引。
- `server/main.py`：`/api/questions/meta` 返回版本元信息。

## 3. 方向三：数据库架构升级

### 3.1 新增表（幂等迁移）
- `study_plans`：
  ```sql
  CREATE TABLE IF NOT EXISTS study_plans (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    user_id INTEGER NOT NULL,
    cat TEXT NOT NULL DEFAULT '',
    plan_json TEXT NOT NULL,
    week_start TEXT NOT NULL,
    is_active INTEGER NOT NULL DEFAULT 1,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (user_id) REFERENCES users(id)
  );
  ```
- `question_bank_versions`：见 2.2。

### 3.2 索引补充
```sql
CREATE INDEX IF NOT EXISTS idx_study_plans_user_active ON study_plans(user_id, is_active);
CREATE INDEX IF NOT EXISTS idx_wrong_book_qid ON wrong_book(question_id);
CREATE INDEX IF NOT EXISTS idx_quiz_records_created ON quiz_records(created_at);
```

### 3.3 兼容与迁移安全
- 全部 `CREATE TABLE/INDEX ... IF NOT EXISTS`，老库升级只追加不破坏；`init_db()` 在 `lifespan` 已调用，启动即生效。
- 升级前由部署脚本对 `coach.db` 做备份（测试阶段在临时库验证）。
- **PostgreSQL 迁移路径**（本期不切换，仅留接口）：DDL 差异已注明——自增改 `SERIAL`/`IDENTITY`、JSON 改 `JSONB`、`PRAGMA` 改连接参数、`IF NOT EXISTS` 两库通用。数据库路径经 `DB_DIR` 环境变量集中，便于切换。

### 3.4 修改点
- `server/database.py`：新增两张表 + 索引。
- `server/models.py`：新增 `StudyPlanIn / StudyPlanOut / QuestionBankVersionOut`。

## 4. 方向四：AI 学习计划

### 4.1 后端端点
- `POST /api/study-plan`
  - 入参：`{ user_id: int|null, cat: str|null, days: int = 7 }`。
  - 逻辑：
    - 登录用户：聚合 `mastery`（`/api/mastery` 同款查询）、近期 `quiz_records`、`wrong_book`、`daily_streaks` → 构造上下文。
    - 匿名（`user_id=None`）：用题库总体分布（来自 `questions/meta` 的 `topics`）生成**示例计划**，不读个人数据。
    - 调用 `_structured_llm(system, user, "study_plan", _PLAN_SCHEMA, max_tokens=900)` 生成结构化周计划。
    - 失败/无 Key → 降级模板：按 `mastery` 升序取 Top-N 薄弱知识点铺满 `days` 天，确定性输出。
  - 出参：`{ fallback: bool, plan: { week_start, days:[{day, theme, topics, count, tip}] } }`。
- `GET /api/study-plan/{user_id}`
  - 读 `study_plans` 中该用户 `is_active=1` 的一条；无则返回空。
  - 保存由前端在登录态调用 `POST /api/study-plan`（生成后）再 `POST /api/study-plan/save`（或合并为生成即保存）。本期采用：前端「生成」→「保存」两步；保存端点 `POST /api/study-plan/save` 做 `UPSERT`（先置旧 `is_active=0`，再插新）。

### 4.2 前端视图（新增 `#view-plan`）
- 导航新增「学习计划」按钮；视图含：目标分类选择、天数、`生成计划` 按钮、计划卡片渲染区、`保存计划`（仅登录）、`follow` 提示。
- 匿名用户：生成即预览，提示登录后可保存。
- 渲染 `days` 为每日卡片（Day1 主题/知识点/题量/贴士）。

### 4.3 新增/修改点
- `server/models.py`：`StudyPlanIn / StudyPlanOut / StudyPlanSaveIn / PlanDayOut`。
- `server/main.py`：新增 `_PLAN_SCHEMA`、`/api/study-plan`、`/api/study-plan/{user_id}`、`/api/study-plan/save`；`fallback_study_plan()`。
- `coach.html`：`#view-plan` 视图 + JS（`initStudyPlan / generateStudyPlan / saveStudyPlan / renderStudyPlan`）；`switchView` 增加 `plan` 分支。

## 5. 安全与兼容性红线

1. **体验模式不回归**：所有原匿名可用路径（`/api/questions/meta`、`/api/quiz/check`、各 demo 渲染）保持不变；学习计划匿名预览同样不读个人数据。
2. **密码安全**：沿用加盐 SHA-256（`verify_password` 兼容无盐旧库），本期不涉及改动，审查阶段复核。
3. **注入防护**：所有 DB 访问用参数化查询；`plan_json` 以 JSON 文本存储，读取后 `json.loads`，无拼接 SQL。
4. **CORS**：维持 `allow_origins=["*"]`（同源部署可接受；若上公网需收紧，列为审查项）。
5. **LLM 输出**：结构化 schema 约束 + 降级兜底，任何情况下 `/api/study-plan` 都返回 200。
