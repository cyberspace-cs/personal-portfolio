# 面试题目（Agent 应用开发）· 附回答要点

> 覆盖：架构编排 / 记忆 / RAG / 工具 / 反思评测 / AIOps 迁移 / 部署工程 / 行为深挖 / 开放设计。
> 每题给「考察点 + 回答要点」，要点尽量锚定本项目真实实现，方便你现场举例。

---

## 一、Agent 架构与编排

**Q1. 你为什么用 LangGraph 同构的 StateGraph，而不是直接 if/elif 调度？**
- 考察：对 Agent 编排范式理解。
- 要点：① 子 Agent 关系显式成图，可扩展、可观测；② 条件边做 Supervisor 路由，最大步数防环；③ 同构 API 让生产可一键换 `langgraph.graph.StateGraph`，零改业务逻辑。→ 本项目 Phase D 把 orchestrator 的 if/elif 重写为 6 节点图。

**Q2. 多 Agent 协作里怎么避免死循环 / 无限调用？**
- 要点：① 图结构 + `set_finish_point` 明确终点；② 最大步数上限（本项目 Supervisor 引擎带 max_steps）；③ 反思节点为确定性校验，不新开 LLM 调用。

**Q3. Supervisor 路由的意图识别怎么做？为什么不用独立分类模型？**
- 要点：轻量规则 + LLM 分类二选一；本项目无 Key 时走关键词/规则路由，有 Key 走 LLM 意图分类，兼顾可跑与精度。

## 二、记忆管理

**Q4. 你的分层记忆怎么设计？短期和长期分别存什么？**
- 要点：短期=滑窗最近 12 轮对话（agent_short_term 表）；长期=用户画像/最近诊断薄弱点/最近计划重点（agent_profile 表）；SQLite 持久化，重启不丢。

**Q5. 上下文超长怎么办？你怎么控制成本？**
- 要点：五段式上下文预算（身份/长期画像/诊断摘要/对话历史/当前），每段独立限额，保证「当前用户消息」永不被裁（优先级最高）；短期滑窗超出 12 轮删最旧。

**Q6. 多会话怎么隔离？清记忆要不要清画像？**
- 要点：`session_id` 隔离会话；`/api/agent/session/clear` 只清短期记忆，保留长期画像（用户资产不丢）。

---

## 三、RAG 与防幻觉

**Q7. 你的 RAG 召回和重排怎么做的？**
- 要点：两路召回（TF-IDF 语义 + 中文 2-gram 关键词）→ RRF 融合重排（score=Σ1/(K+rank), K=60）；生产可换向量库+BM25 同构。

**Q8. 你怎么保证「不幻觉」？**
- 要点：① 相关判据仅依赖 2-gram 关键词真实命中（`bg_overlap>=1`），不靠相似度虚高；② 不相关→明确拒答，绝不调 LLM 编造；③ 系统提示强制「仅基于引用、论断标 [n]、不足明说」；④ 评测闭环用 `hallucination_rate`（设计目标=0）量化。

**Q9. 引用溯源怎么落地的？**
- 要点：`format_citations` 生成 [1][2]，检索结果带 title/content；LLM 作答在论断后标 [n]，来源可点回知识点/错题。

## 四、工具调用（Tool Use / Function Calling）

**Q10. 工具网关要解决哪些问题？**
- 要点：重复调用拦截、参数校验、高风险审批、超时；本项目 `CoachTools` 统一封装 get_mastery/get_wrong_book/rag_qa 等，网关做去重与超时。

**Q11. 模型怎么「知道」该调哪个工具？**
- 要点：意图路由决定走哪个子 Agent；子 Agent 内确定性调用对应工具（本项目为保证零依赖可跑用规则触发，生产可换 function calling schema 让模型自选）。

---

## 五、反思与评测闭环

**Q12. 你的「反思 Agent」是真的再调一次 LLM 吗？**
- 要点：本项目用确定性校验节点（诊断后推计划、计划后推打卡、RAG 后推追问），保证每次响应都有下一步动作且零依赖；真实场景可在 reflect 再挂 LLM 自评（回答是否基于引用/是否越界）。

**Q13. 怎么量化评估一个 Agent 的好坏？**
- 要点：评测闭环——每次 RAG 调用落 `agent_eval_log`，聚合 `hit_rate / citation_rate / reject_rate / hallucination_rate` + 分级 A/B/C；`run_self_eval` 内置样本自评估，无真实流量也能演示。

**Q14. 你踩过的评测口径坑？**
- 要点：把「拒答」（未作答的正确防幻觉行为）误算成幻觉 → `hallucination_rate` 虚高；修正为仅统计「声称作答却不相关」。结论：指标口径必须对齐系统真实语义。

## 六、AIOps 迁移 / 主动性

**Q15. 你把 AIOps 异常检测迁移到学习场景，怎么映射的？**
- 要点：指标突降(QPS骤跌) → 正确率骤降（时间序列切 baseline/recent 比均值差）；指标中断 → 连续断签（日期连续缺失天数）；指标抖动 → 错题反复（error_count 阈值）。detect() 接口同构，生产可换 Z-score/EWMA/孤立森林。

**Q16. Agent 怎么「主动」找用户，而不是等问？**
- 要点：诊断节点接入 `LearningAnomalyDetector`，诊断即扫描异常并 `format_alert` 主动推送预警文案（anomaly_alert + cards.anomaly 随响应返回）。

---

## 七、部署与工程

**Q17. 没有 API Key 怎么跑？降级策略？**
- 要点：HAS_KEY 开关，无 Key 走模板/规则作答（如 `_fallback_rag_answer`），主链路不依赖外部密钥；有 Key 走真实 LLM。便于演示与离线评测。

**Q18. 基座私有化怎么考虑？**
- 要点：混元/通义开源权重 + vLLM/SGLang 私有化，呼应 LLM 推理开发岗；量化降成本；上下文预算控显存/Token。

**Q19. 怎么保证服务可运维？**
- 要点：FastAPI lifespan 启动时建表（agent_profile/agent_short_term/agent_eval_log）；版本号语义化（3.4.0-anomaly）；所有工具调用留痕可审计。

## 八、行为 / 项目深挖

**Q20. 这个项目你最自豪的一个决定是什么？**
- 建议答：把「防幻觉」做成默认行为（低相关拒答）而非事后修补——这是 Agent 可信的前提，也是面试差异化。

**Q21. 如果给你两周做 v2，你会先补哪块？**
- 建议答：① 真实向量库（Milvus）替换 TF-IDF；② 反思节点升级 LLM 自评闭环；③ 多用户压测 + 评测集扩充到可回归基线。

**Q22. 你一个人的项目，如何体现工程规范？**
- 要点：分阶段 Phase A–E 各自编译+冒烟（隔离 DB）；文档即设计稿；Git 提交粒度清晰；无外部依赖可跑。

## 九、开放设计题（练手）

**Q23. 设计一个「备考 Agent」的多 Agent 协作方案。**
- 框架：Supervisor（意图）→{诊断/讲题/变式/规划/答疑}→反思→（异常检测定时任务）。强调工具网关、记忆、RAG 引用、评测闭环四点。

**Q24. 如何让 Agent 的回答「可解释、可追溯」？**
- 要点：检索即留痕、引用编号、低相关拒答、评测日志、工具调用留痕——五道保险。
