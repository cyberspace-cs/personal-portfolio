### AI 产品经理专项（7 题）
1. **Q**：如何定义一款 Agent 产品？
   **A**：从用户真实痛点出发(非技术炫技)；定义角色边界、何时用工具、如何评估效果，而非「套个聊天框」。
2. **Q**：如何设计 Agent 产品指标？
   **A**：四率(命中/引用/拒答/幻觉)+A/B+留存/转化；用数据反推功能优先级。
3. **Q**：竞品分析怎么做？
   **A**：按能力/场景/定价/生态拆维度，找差异化切入点(如可解释、低代码、垂域)。
4. **Q**：低代码/自然语言构建 Agent 的产品价值？
   **A**：抹平技术鸿沟，让业务/非技术同学自助搭建，沉淀 Agent 生态与留存。
5. **Q**：技术团队冲突如何同频推进？
   **A**：用 PRD+技术边界共识+指标对齐；能读得懂 LangGraph/MCP/RAG 以评估可行性。
6. **Q**：0→1 产品如何验证？
   **A**：MVP+开源复用快速验证，成本自负盈亏；用数据证明需求与商业化可行。
7. **Q**：Agent 产品如何做可解释与信任？
   **A**：引用溯源、过程可见、可纠错；信任是 C 端留存核心卖点。

### Agent 系统设计（14 题）
1. **Q**：什么是 Agent？与大模型本质不同？
   **A**：Agent = 思维链 + Function Calling + 循环；模型自主决定下一步，而非逐步指挥（概率性自主运行）。
2. **Q**：Agent 核心组件？
   **A**：规划(Planning) + 记忆(Memory) + 工具(Tools) + 执行(Execution) + 反思(Reflection)。
3. **Q**：Workflow / Agent / Tools 区别？
   **A**：Tools 是原子能力；Workflow 是固定编排(确定性)；Agent 是模型动态决策(概率性)。
4. **Q**：ReAct 是什么、如何实现？
   **A**：Reason+Act 交替：先推理再调工具观察结果，循环至完成；实现上每轮输出 Thought/Action/Observation。
5. **Q**：ReAct / Plan-and-Execute / Reflection 区别与选型？
   **A**：ReAct 边想边做(简单)；Plan-and-Execute 先整体规划再执行(复杂长任务)；Reflection 加自评纠偏(质量要求高)。
6. **Q**：复杂任务如何拆分？为什么要拆分？
   **A**：拆成明确输入输出的子任务，便于校验/并行/回滚；单任务失败不影响整体。
7. **Q**：记忆机制如何设计(短期/长期)？
   **A**：短期=最近N轮+工作记忆(关键约束)；长期=向量库/SQLite 外部存储按需检索；分层+衰减。
8. **Q**：记忆压缩有哪些方法？
   **A**：滑动窗口、对话摘要、关键信息提取(决策/约束/偏好每轮注入)、向量库检索长期。
9. **Q**：多 Agent 如何协作与动态切换？
   **A**：Supervisor 拆任务→Worker 并行→Synthesizer 汇总；消息队列解耦；按任务复杂度动态选子 Agent。
10. **Q**：为什么有时手搓 Agent 而非用框架？
   **A**：框架有抽象开销/黑盒；手搓对循环、记忆、工具调用完全可控，便于调试与极致优化。
11. **Q**：如何赋予 LLM 规划能力？
   **A**：Prompt 引导分步 + 外部 Planner/ReAct + 任务树；复杂场景用 Plan-and-Execute。
12. **Q**：反思机制是什么、为什么、怎么实现？
   **A**：让模型/独立检查 Agent 复盘输出矛盾并回退重规划；防环防偏；节点校验+循环检测。
13. **Q**：如何解决上下文漂移？
   **A**：每轮注入原始目标 + 阶段性总结 + 上下文压缩 + 独立监督 Agent 拉回。
14. **Q**：如何防止工具调用幻觉？
   **A**：严格工具 Schema + 工具白名单(执行层拦截未注册) + 参数校验(类型/枚举)。

### RAG 检索增强（8 题）
1. **Q**：RAG 原理与全链路？
   **A**：切分→Embedding→向量库→检索→重排→拼上下文→生成；落地链路要可观测可评估。
2. **Q**：文档如何切分？Chunk 大小怎么定？
   **A**：512-1024 Token、重叠 50-100；太细丢上下文、太粗不精准，按召回效果调。
3. **Q**：Embedding 选型与向量数据库？
   **A**：Milvus/Pinecone/Weaviate 做相似度检索；语义近则向量近，支持跨语言召回。
4. **Q**：混合检索怎么做？
   **A**：向量(语义)+关键词(精确) 用 RRF 倒数排名融合，比单一检索显著更好。
5. **Q**：Query 改写 / HyDE 是什么？
   **A**：HyDE 先生成假答案再用其 Embedding 检索，与真实文档语义更接近，召回更准。
6. **Q**：Rerank 怎么做、为什么需要？
   **A**：Bi-Encoder 快但不精，用 Cross-Encoder 重排把相关项前置，提升答案相关性。
7. **Q**：如何缓解 RAG 幻觉 / 做引用溯源？
   **A**：检索段落带引用标号 + 末尾强制附引文 + 事实核查；citation_rate/hallucination_rate 量化。
8. **Q**：RAG 效果如何评估？
   **A**：召回率/答案相关性/忠实度(是否编造)；离线四率 + 在线 A/B。

## 4. 话术（STAR 模板 + 本项目定制）
> 以下话术基于本项目「刷题教练 → 定制化备考 Agent v3.1.0-agent-mem」设计，请按你的真实经历微调数据与措辞。

### 评测体系
- **面试官可能问**：你如何做 Agent 评测？
- **话术（STAR）**：S：Agent 效果不能只「能跑」，需可量化可迭代。 T：建立可对比的评测体系指导迭代。 A：离线四率(hit/citation/reject/hallucination) + 在线 A/B + Prometheus 可观测(latency/QPS/命中)；对齐 SWE-Bench/TAU-Bench 工程化思路。 R：用数据反推功能优先级，拒绝兜底与反思节点据此上线，质量可测可控。

### 职业规划
- **面试官可能问**：为什么选 Agent 应用开发 / 为什么投我们？
- **话术（STAR）**：S：看到 2026 招聘从「大模型基础」转向「AI 应用落地」，Agent 是核心。 T：希望在最落地、最需要工程深度的团队打磨。 A：已具备 Agent 框架/RAG 防幻觉/多 Agent/推理优化/评测闭环全链路经验，且持续跟进 MCP/Skill 等 2026 新标配。 R：希望把可量化、可降级的 Agent 落地方法论带到贵司 {岗位}。
