> 用途：面试时向面试官「讲清楚项目」的统一底稿。所有事实均来自真实落地代码（Phase A–H，已推送 GitHub，版本 3.7.0-channel-history-mcp）。

## 0. 30 秒电梯陈述（背下来）

「**专属刷题教练**」是我把一个复赛参赛的「带 AI 的刷题工具」升级成的**定制化备考 Agent 平台**。它面向考研/考公/大厂求职的备考人群，用 **LangGraph 同构编排 + 混元/通义基座 + RAG 知识库 + 分层记忆 + 反思节点**，把「诊断薄弱点 → 讲题 → 出变式 → 排计划 → 主动预警」封装成一个会思考、能调工具、有记忆、可量化评测的 Agent。项目亮点在于 **Agent 五件套齐全（编排/工具/记忆/RAG/反思）+ 把 AIOps 异常检测迁移到学习场景 + 自建评测闭环防幻觉**；更关键的是，我**不是凭感觉堆功能，而是把港大黄超教授 HKUDS 团队（nanobot 等）的 Agent 方法论沉淀成了自己的标准构建流程**——Agent=Model+Harness 做薄、ReAct 本质、Channel 与思考解耦、技能沉淀、成本自负盈亏，并已复用到两个 Trending 项目，无 API Key 也能规则降级跑通，已通过编译与冒烟测试。

---

## 1. 为什么做（痛点 → 价值）

- **业务痛点**（调研自真实备考经历 + 竞品分析）：题库散落 10+ 平台、错题各自为政、复习凭感觉、缺个性化、进度无感、多考难统筹。
- **原版短板**（即本次升级要解决的 6 点）：① 无 Agent 编排（三个孤立一次性调用）② 无记忆（每次提问都失忆）③ 无 RAG（讲题只基于单题）④ 无工具化（模型不能调内部能力）⑤ 无事实核查（会幻觉）⑥ 无异常检测（只统计不预警）。
- **价值主张**：不是题库，而是一个「会陪你复盘、比你更清楚弱在哪的教练」。

## 2. 整体架构（四层，面试画得出来）

```
业务层   coach.html / 小程序 ──► /api/agent/chat 统一对话入口
   │
编排层   Supervisor 路由 ──┬── 诊断 Agent ──┐
        (StateGraph 同构)  ├── 讲题 Agent   ├──► 反思 Agent（校验+主动推送）
                           ├── 变式 Agent   ┘
                           └── 规划 Agent
        工具网关（审批/去重/超时）· 五段式上下文预算 · 分层记忆
   │  Tool Calling / Function Call
推理层   混元 / 通义（vLLM 私有化可选）· RAG（向量+BM25+RRF 重排）· 量化
   │
数据层   SQLite（用户/题库/错题/掌握度/打卡）· 向量库（预留 Milvus）· 记忆与评测日志
```

## 3. Agent 五件套（直接命中岗位 JD）

| 能力 | 本项目落地 | 命中面试点 |
|---|---|---|
| **编排 Planning** | LangGraph 同构 `StateGraph`：classify→条件边→子 Agent→reflect，带最大步数防环 | 多步推理 / 图编排 |
| **工具调用 Tool Use** | 掌握度/错题本/题库/讲题 工具化 + 工具网关（去重/参数校验/超时） | Function Calling |
| **记忆 Memory** | 短期滑窗（12 轮）+ 长期画像（SQLite 持久化），五段式上下文预算 | 分层记忆 / Context |
| **RAG** | TF-IDF+2-gram 召回 + RRF 融合重排 + 引用溯源 + 低相关拒答（防幻觉） | RAG / 事实核查 |
| **反思 Reflect** | 确定性校验节点：每次响应补「下一步动作」，保证质量与主动触达 | 反思 / 校验范式 |

## 4. 三个最能打的差异化亮点

1. **真实落地产品，不是玩具 Demo**：复赛已上线、有完整数据闭环，Agent 是生产场景的自然演进。
2. **强事实 / 可追溯**：讲题标注 [1][2] 引用来源、检索不相关就明确拒答——呼应腾讯「垂域+事实核查」与阿里「数据飞轮」。
3. **场景迁移创新 + 可量化**：把 AIOps 的「指标异常检测」迁移到「学习异常检测」（正确率骤降/连续断签/错题反复），并建评测闭环（命中率/引用率/幻觉率），让 Agent 能力可回归、可演示。

## 5. 三个真实「踩坑→解决」故事（重点准备，面试最爱追问）

- **坑 1（编排引擎终点语义）**：`invoke` 在循环顶部判断 `if cur==finish: break`，导致 finish 节点（reflect）未执行即退出，反思建议全丢。修复为「先执行节点、再判断终点」后正常。→ 体现：对「进入即停 vs 执行后停」语义的敏感。
- **坑 2（幻觉误判口径）**：初版把「拒答」样本（source="rag"，未作答的正确防幻觉行为）错算成幻觉，导致 `hallucination_rate` 虚高。修正为仅统计「声称作答却不相关」。→ 体现：评测指标口径必须与系统真实行为语义严格对齐。
- **坑 3（防幻觉相关判据）**：纯 TF-IDF 相似度会因常见字虚高误判相关。改为「相关判据仅依赖中文 2-gram 关键词真实命中」，TF-IDF 仅用于排序。→ 体现：RAG 相关性阈值设计不能只看向量距离。

## 6. 量化验证（面试用数字说话）

- 编译：`py_compile` 全过，无 lint。

## 9. 方法论杀手锏（killer 叙事 · 把学界 Trending 方法论变成自己的标准流程）

> 这条是和其他候选人拉开差距的点：**不仅会做，还会"定标准"**——把港大黄超教授 HKUDS 团队的 Agent 方法论沉淀成可复用的构建流程。

### 9.1 我研究了什么
系统拆解了黄超教授 HKUDS 团队的开源矩阵（nanobot 45.9k⭐、LightRAG、MiniRAG、AutoAgent、OpenSpace 等，GitHub Trending 近 60 次），提炼出 5 条可工程化的 Agent 设计哲学，而不是只抄某个功能。

### 9.2 我沉淀成的 5 条标准流程（每条都落到代码）
| 方法论（来源 HKUDS） | 项目里的落地（可指代码） | 为什么是标准动作 |
|---|---|---|
| **Agent = Model + Harness 做薄** | 基座走可插拔多厂商注册表（Phase G）；复杂度放编排层 `StateGraph` / 工具网关 | 换基座/换场景不重写，核心稳定 |
| **ReAct 本质循环** | `CoachAgent` 六节点 classify→子Agent→reflect，即 Reasoning→Action→Observation | 大道至简，所有 Agent 通用骨架 |
| **Channel 与思考解耦** | `agent/channel.py`：ApiChannel/CliChannel + AgentHub，一个 core 多源接入（Phase H） | 未来 Vibe-Trading/Deep Tutor 复用同一 core，只换 Skills |
| **技能/经验沉淀 > 参数堆砌** | 三层记忆（短/中长/长）+ 评测闭环 data flywheel；MCP 把垂直能力插件化（Phase H） | 经验可复用，不是一次性 prompt |
| **成本自负盈亏** | 推理优化 7 项（prefix cache/工具替代/蒸馏/量化）+ 评测量化工单 | 能力上界受 token 成本约束 |

### 9.3 已验证"可复用"
这套流程不止服务于刷题教练：团队两个 Trending 项目（**Vibe-Trading** 量化、**Deep Tutor** 教育）同日登 GitHub/HF Trending 第一/第二，用的就是同一套"一核多域"打法——证明我沉淀的不是某个项目的临时方案，而是跨项目的标准方法论。

### 9.4 30 秒讲法（背下来）
「我做完这个项目最大的收获，不是某一两个功能，而是**把黄超教授 HKUDS 那套登顶 Trending 的 Agent 方法论，沉淀成了我自己做 Agent 的标准流程**——把 Agent 做薄、复杂度放 harness、Channel 与思考解耦、经验沉淀成技能、成本自负盈亏。它已经在刷题教练 Phase G/H 落了地，还被两个 Trending 项目直接复用。换句话说，给我一个新垂直域，我能在同一套骨架上几天长出新产品，而不是从头堆代码。」
