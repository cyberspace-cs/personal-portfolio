你每天见的网页，背后跑的"运输协议"版本可能都不一样。差别有多大？直接看账。

HTTP/1.1 像一辆一次只拉一件货的卡车。同一个域名，浏览器通常最多开 6 条并行连接。一个页面有 80 个资源，就得在这 6 条车道上排队，前一个没结束，后一个干等。4G 下加载这种页面要 2-3 秒。你刷手机时那种"图半天不出来的卡顿"，很多时候就是队头阻塞——一张大图卡在队首，后面几十个小请求全干等。

HTTP/2 改成多路复用——一辆卡车同时拉几十件货，所有请求在一个连接上并行。还是那 80 个资源，换成 /2 能压到 1-1.5 秒，快 30%-50%。对开发者几乎透明，服务器开个开关就行。代价是 /2 搞了个"流"的概念，单条流内部仍有优先级阻塞，不过比起 /1.1 已经好太多。

HTTP/3 更进一步，底层换 UDP 的 QUIC 协议。它顺手解决了 TCP 的队头阻塞（一个包丢了会卡住后面所有包），还把 TLS 握手和传输握手合并，建连更快。丢包率 2% 的弱网里，/3 比 /2 还能快 10%-30%。现在主流浏览器默认支持。你可以打开开发者工具的 Network 面板，看 Protocol 列——标 h2 或 h3 的就是对应版本。我习惯每次上线后扫一眼，确认没意外退回 h1。

服务器回的"运单"上有状态码，几个最常见的：
- 200：订单完成，包裹在此。
- 301/302：这页搬家了，去新地址（常用来强制 HTTPS）。
- 401/403：前者是"你没登录"，后者是"登录了也没权限"——别混。
- 404：查无此商品。
- 429：你太猛了，被限流。
- 500：仓库内部炸了。

状态码不是装饰，是 debug 的透镜。我见过最烦的一个 case：一个站点配置了"http 强制跳 https"，https 又配了"非 www 跳 www"，两层重定向叠一起，浏览器直接报"重定向次数过多"打不开。看懂 301 的链条，你一眼就能定位是配置循环，而不是怪用户网络。还有一次，一个接口偶发 429，前端狂重试反而把限流越踩越死——正确的做法是在客户端做退避，而不是无脑重试。

补几个实用点。HTTP 本身是无状态的——服务器不记得你上一次请求是谁。所以"登录态"靠 cookie/session 或 token 补上：浏览器每次请求自动带 cookie，服务器据此认人。很多新人搞不懂"为什么接口突然让我重新登录"，其实就是 token 过期了。

HTTP/2 还带来过一个叫"服务器推送"的特性，让服务器主动把 CSS/JS 推给客户端，省一次往返。听起来美好，实测常因为"推了你不需要的东西"反而变慢，加上缓存策略难搞，到 2026 年基本被弃用，主流框架也不再推荐。技术圈的"看起来很美"和"真的好用"之间，常差着一地实践教训。

想升级你的站点？Nginx 加两行配置就能开 /2 和 /3，几乎零成本换来肉眼可见的提速。改完记得用开发者工具的 Protocol 列确认生效。另外，gRPC 这种现代 RPC 框架底层就跑在 HTTP/2 上——它把"方法调用"编码成 HTTP 请求，享受多路复用。所以你以为的"高级协议"和"老 HTTP"其实是一家，别被名词吓住。

再补一个天天用却常忽略的点：HTTP 缓存。服务器可以回 `Cache-Control: max-age=3600` 告诉浏览器"这一小时内别再来找我"，或者回 `ETag` 让浏览器下次带 `If-None-Match` 问"这资源变没变"，没变就回 304 Not Modified，省下整份传输。我优化过一个首屏 3 秒的站点，光是把静态资源缓存头配对，二次访问直接降到 300 毫秒——用户以为我重构了，其实只是加了几个响应头。

所以状态码里 304 也值得认识：它不是错误，是"你本地那份还新鲜，接着用"。把缓存、状态码、协议版本这三样串起来，你才算真懂 HTTP。

说个我亲身经历的账。一个老项目一直跑在 HTTP/1.1，首屏要 2.8 秒，用户投诉"打开慢"。我先在 Nginx 上加了 `http2 on;`，啥业务逻辑没动，首屏直接掉到 1.6 秒——光靠多路复用把 80 个资源的排队消除了。再配合上一节说的静态资源缓存头，二次访问干到 300 毫秒。前后不到一小时，体验像换了个站。这就是协议版本和缓存叠加的威力，而且几乎零成本。

HTTP/3 还有个更妙的东西叫 0-RTT 恢复。你第一次连上某站点后，客户端会缓存一份加密参数；下次再连，第一个数据包就能直接带上请求数据发出去，不用等握手往返。对重复访问的站点（比如你每天开的后台系统），这能省掉整整一次网络往返的延迟。代价是 0-RTT 数据有被重放的微弱风险，所以一般只用来发"幂等"的请求（比如 GET），不用来发会改状态的 POST。安全和速度的取舍，协议设计里处处都是。

怎么确认你的站点用的是哪版？终端里 `curl -I --http2 https://你的域名`，看返回头里有没有 `alt-svc` 或协议协商信息；浏览器开发者工具的 Network 面板 Protocol 列更直接，h2/h3 一目了然。我每次上线必扫一眼——有时候你以为开了 /2，结果证书链配错导致协商失败，悄悄退回了 /1.1，性能白白丢一半。

HTTP/3 还有个 TCP 做不到的本事：连接迁移。你手机从 WiFi 切到 4G，IP 变了，TCP 连接会直接断掉、得重新握手（页面会卡一下）；QUIC 用"连接 ID"标识会话而不是用 IP+端口，换网络后同一个连接 ID 还能接着用，视频通话、直播这类场景体验差别很大。想在自己站点开 /3，Nginx 加 `listen 443 quic; http3 on;` 并配好证书即可——前提是你的 TLS 库够新。开完同样用开发者工具 Protocol 列确认 h3 生效，别闷头配了半天，结果协商失败悄悄退回 h1。

一句话记住：协议版本和缓存是免费的性能，上线前花十分钟确认开了，比上线后救火划算十倍。
