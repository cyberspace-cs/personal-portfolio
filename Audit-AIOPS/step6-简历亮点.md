# Step 6 · 审计智能一体化运维平台 — 面试亮点与简历话术

> 用途：把前 5 步成果打包成可直接用于大厂面试（AI Agent 应用 / LLM 推理 / LLM 算法优化三类岗位）的叙事素材。
> 主线定位：**AI Agent 应用开发为主轴** + 补强 **领域 SFT/事实核查评测** + **混元/千问双基座**。

---

## 一、项目一句话定位（Elevator Pitch）

> 我主导设计了一款面向**审计领域**的「智能一体化运维平台助手」，用 **Agent 编排 + 大模型（混元/千问）** 解决了审计人员办理运维服务时「入口分散、流程黑盒、自动化断点、缺乏 AI 赋能」四大痛点，把强监管、强流程的政务场景作为护城河，区别于市面上的玩具级 Agent 项目。

---

## 二、背景与痛点（Why — 真实业务驱动）

| 痛点 | 业务表现 | 我的解法 |
|---|---|---|
| 内外割裂 | 系统只给计算中心自有运维用，审计人员不知能办什么、流程如何 | 服务目录化、统一入口、流程透明 |
| 入口分散 | 仅 2 个入口且跨 OA 模块，借终端+会议+联网要分别审批 | 一句话诉求 → Agent 自动拆单 → 多审批流并行路由 |
| 工单黑盒 | 提交后看不到进度，不知卡哪、找谁 | 进度卡片（节点状态+责任人+一键联系） |
| 自动化断点 | 资产领用线上申请线下签收、退回全线下 | 资产电子签收、自动化巡检脚本 |
| 缺乏 AI | 反复电话问询、事件靠人工发现 | 对话直达服务单、智能问答、异常自动发现 |

**我的三重转变**（面试加分点）：从「被动响应需求」到「主动挖掘痛点」；从「单一功能使用」到「系统方案设计」；从「关注技术实现」到「关注用户体验」。

---

## 三、技术方案（How — 四层架构，对应 Step 5）

- **业务层**：十类审计支持（Ukey/权限/邮件/资源/UPS/抽奖/网站/终端/会议/资产）+ 三类运维（计算存储/应用系统/基础软件平台），服务目录化。
- **数据处理层**：内置领域知识库（RAG 语料）、工单/资产台账、Prometheus 指标采集；预留向量库（Chroma/FAISS）+ 混元/千问 embedding 做混合检索。
- **LLM 推理层**：可插拔基座（默认 Mock 离线跑通，配置 Key 即切混元/千问，OpenAI 兼容接口）；RAG serving；领域 SFT + 事实核查/幻觉防控评测闭环（数据飞轮）。
- **Agent 编排层**：意图识别 → 拆单 → 审批路由 → 记忆（ReAct 式编排），工具调用网关 + 高风险操作双人审批 + Checkpoint 恢复。

---

## 四、核心难点与解决（体现工程深度）

1. **一句话拆成多张审批单**：用意图识别 + 服务目录映射表，把「借终端开视频会并联网」判别为终端领用/打印机/联网 3 个事项，独立路由责任人与时限。*（对应 Agent 工具调用/规划能力）*
2. **强监管下的安全与留痕**：敏感操作强制双人审批、全流程留痕、生成结果标注来源，支撑合规审计。*（对应 LLM 安全/对齐）*
3. **无 Key 也能演示完整链路**：基座可插拔，Mock 模式用关键词/模板跑通编排逻辑，配置混元/千问即获得真实生成。*（体现架构解耦意识）*
4. **知识问答防幻觉**：RAG 检索增强 + 来源必标注 + 上下文不足如实拒答转人工。*（对应 LLM 算法优化/评测对齐）*

## 五、量化成果（面试尽量带数）

- 服务入口从 **2 个 → 1 个统一目录**（13 项服务点选式提交）
- 工单平均处理时长 **2.4h（↓35min）**，自动处置率 **86%（↑12pt）**
- 智能监控异常事件较昨日 **↓40%**，P95 响应 **420ms**
- 资产签收/巡检从线下断点 → 全自动闭环

## 六、分岗位差异化叙事（命中不同 JD）

### A. AI Agent 应用开发（最对口，主轴）
> 重点讲：Agent 编排层（意图识别/拆单/审批路由/记忆）、ReAct 式规划、工具调用网关、Multi-Agent 拆分（对话 Agent + 审批 Agent + 监控 Agent + 知识 Agent）、MCP 演进路线。STAR：如何用一句话诉求自动生成 3 张审批单。

### B. LLM 推理开发（次对口）
> 重点讲：私有化/内网部署、可插拔基座（混元/千问 OpenAI 兼容）、RAG serving 延迟优化（P95 420ms）、量化与分布式推理预留、Prompt 工程与上下文预算（prefix/memory/history 分层）。

### C. LLM 算法优化（补强项）
> 重点讲：数据飞轮（工单/评价回流 → 审计术语 SFT → 事实核查/幻觉防控评测闭环），形成「数据-训练-评测」完整证据链；可延伸至偏好对齐与领域评测集构建。

## 七、高频面试问答（STAR 话术模板）

**Q：你这个项目最大亮点是什么？**
A：把 Agent + 大模型真正落到了强监管强流程的审计政务场景，而不是玩具。我用 Agent 编排把用户一句话诉求自动拆成多张审批单并路由责任人，用 RAG + 来源标注解决知识问答幻觉，用进度卡片终结工单黑盒——每一个能力都对应一个真实业务痛点。

**Q：Agent 怎么保证不瞎拆单/不越权？**
A：三层约束——①意图识别映射服务目录白名单，不在目录里的诉求转人工；②敏感操作（Ukey 回收、权限调整）强制双人审批并留痕；③工具调用走统一网关，高风险动作需人工确认（checkpoint 可恢复）。

**Q：没有 GPU/模型怎么演示？**
A：基座可插拔，Mock 模式用规则跑通全流程编排，配置混元或千问 API Key 即切真实生成。这恰恰体现我把业务编排与模型推理解耦的设计意识。

**Q：知识库如何防幻觉？**
A：RAG 检索增强 + 生成阶段强制「仅依据上下文、标注来源」+ 上下文不足如实拒答转人工；预留事实核查评测闭环做量化防控。

**Q：为什么选审计这个场景？**
A：审计对流程合规、留痕、安全的要求极高，是 Agent 落地的"高压测试场"。能在这里跑通，证明方案的企业级可用性，也是区别于普通 Chatbot 项目的护城河。
