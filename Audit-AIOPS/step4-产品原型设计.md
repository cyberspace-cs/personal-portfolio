# Step 4：产品与原型设计（痛点 → 需求 → 原型）

> 输入：用户自述「十类审计工作支持 + 三大类日常运维 + 五大痛点 + 三重转变」。
> 目标：梳理产品痛点与需求，产出原型设计（统一入口 / 服务目录化 / 进度卡片 / 自动化 / AI 赋能）。AI 能力映射见 Step 3。

---

## 一、业务全景

### 1.1 十类审计工作支持（一线服务，做深做细）
| # | 支持项 | 类型 | AI/自动化机会 |
|---|---|---|---|
| 1 | Ukey 制作、调整与回收 | 资产/权限 | 生命周期自动跟踪、到期回收提醒 |
| 2 | 人员角色权限变更 | 权限 | 审批流自动发起、权限对账 |
| 3 | 远程邮件帐号及容量调整 | 帐号 | 标准化参数自动配置 |
| 4 | 计算存储资源发放 | 资源 | 配额校验、自动发放 |
| 5 | UPS 应急演练支持 | 演练 | 演练脚本自动化、报告生成 |
| 6 | 年会抽奖软件开发演示 | 活动 | 一次性开发（低优先级） |
| 7 | 专网网站改版技术支持 | 网站 | 内容/模板支持 |
| 8 | 终端领用或维修 | 资产 | 资产自动签收确认（痛点四） |
| 9 | 视频会议预约 | 会议 | 与终端/打印机/联网审批联动（痛点二） |
| 10 | （其他常规支持项） | — | 服务目录持续扩充 |

### 1.2 三大类日常运维（运行保障底座）
1. **计算存储设备运维**：服务器、存储、UPS、网络设备的巡检与故障处理。
2. **应用系统运维**：业务应用发布、监控、变更、故障恢复。
3. **基础软件平台运维**：数据库、中间件、操作系统等平台软件。

## 二、五痛点 → 需求映射

| 痛点 | 现状 | 产品需求 | 对应 Agent/LLM 能力（Step 3） |
|---|---|---|---|
| **一、内外割裂** | 系统仅自有运维可见；审计不知能办什么/什么流程；自有运维不知为什么办；外包无法记录 | ① 统一服务目录，按角色呈现视图（审计人员：能办什么+流程；自有运维：为什么办；外包：工作记录）② 操作全留痕 | 权限与留痕（pico 工具审计日志 + DocAI 部门权限）；结构化记忆（用户/角色画像） |
| **二、入口分散且记忆负担重** | 仅终端领用/维修、视频会议预约 2 入口，分散 OA 不同模块；借终端+打印机+联网需分别审批，常漏批 | ① 统一入口 ② 服务目录化、点选式提交 ③ 系统按事项自动拆分执行不同审批流 | 意图识别 Agent + 规划 Agent 自动拆单；MCP 接入各审批系统 |
| **三、工单进度黑盒** | 提交后无法跟踪、看不到审批状态，不知卡在哪/找谁 | ① 进度卡片：各审批节点状态一目了然 ② 一键直达责任人 | 工单状态机 + 进度卡片前端；通知/企微直达 |
| **四、自动化断点** | 资产领用线上提、线下签；退回全线下；仅部分巡检自动化 | ① 重复性标准化操作全自动化：资产自动签收、自动化巡检脚本 | 工具调用 Agent + 自动化巡检；checkpoint 断点续办（pico） |
| **五、缺乏 AI 赋能** | 审计人员反复电话问询；运维事件智能发现/处置空白 | ① 智能问答 ② 语音识别 ③ 智能判别事项 ④ 自动生成工单 ⑤ 对话直达服务单入口 | RAG Agent（知识问答）+ FunASR（语音）+ 意图/规划 Agent（自动拆单生成工单）+ AIOps（异常发现→工单） |

## 三、产品信息架构（原型骨架）

```
审计智能运维助手（统一入口：Web / 企微 / 移动）
├── ① 智能对话入口      ← 语音/文字 → 意图识别 → 自动拆单/路由
├── ② 服务目录          ← 分类：审计支持(10类) / 运维(3类)，点选式提交
├── ③ 我的工单          ← 进度卡片列表（状态/责任人/SLA）
│     └── 工单详情 = 进度时间线（待提交→审批中→执行中→完成）
├── ④ 自动化中心        ← 巡检任务、资产签收、批量操作、异常事件
├── ⑤ 知识库            ← 运维知识 / 审计制度 / 服务目录说明（RAG 检索）
└── ⑥ 管理视图（按角色）
      ├── 审计人员：能办什么、流程是什么
      ├── 自有运维：为什么办、SLA、知识沉淀
      └── 外包人员：工作记录、打卡式任务
```

## 四、关键页面原型（文字线框）

### 4.1 统一入口首页
```
┌─────────────────────────────────────────────┐
│  审计智能运维助手         [角色：审计人员]    │
├─────────────────────────────────────────────┤
│  🎤 说句话就行：                              │
│  "我要借终端开视频会并连因特网"  [发送]       │
│   → AI 自动识别：需拆分 3 条审批，已生成工单   │
├──────────────┬──────────────┬───────────────┤
│ 服务目录      │ 我的工单      │ 自动化中心     │
│ · Ukey        │ ▢ WO-0421    │ · 今日巡检     │
│ · 权限变更    │ ▢ WO-0418    │ · 资产签收     │
│ · 邮件帐号    │ ···           │ · 异常事件     │
│ · 资源发放    │              │               │
│ · 终端/会议   │              │               │
└──────────────┴──────────────┴───────────────┘
```

### 4.2 进度卡片（痛点三解法）
```
工单 WO-0421 · 借终端+视频会+联网        [SLA 剩 4h]
────────────────────────────────────────
✅ 提交申请        张审计    07-19 09:12
✅ 终端领用审批    李运维    07-19 09:40
🔵 打印机审批中    王主管    [一键催办/直达]
⚪ 联网审批        待处理
⚪ 执行发放        待执行
[节点状态·责任人·预计耗时 一目了然]
```

### 4.3 对话直达工单（痛点五解法）
```
用户(语音/FunASR): "UPS 应急演练下周要做，帮我准备"
AI: 识别为「UPS应急演练支持」，已拆为：
   - 生成演练方案(知识库检索)
   - 预约设备停机窗口(审批)
   - 编排自动化脚本(工具调用)
   → 已生成工单 WO-0422，是否确认提交？[确认][修改]
```

## 五、AI 能力落点（来自 Step 3，一一对应）

| 用户诉求 | 平台能力 | 技术方案 |
|---|---|---|
| 智能问答 | 运维知识助手 | 多路 RAG（向量+BM25+RRF）+ 引用溯源（DocAI + 面试攻略） |
| 语音识别 | 对话入口 | FunASR 语音→文本（痛点五） |
| 智能判别事项 | 意图识别 Agent | 规划 Agent 自动拆单（DocAI PlanExecute / pico 编排） |
| 自动生成工单 | 工具调用 Agent | MCP 接 OA/审批系统，自动发起（pico 工具网关+高风险审批） |
| 进度可视 | 进度卡片 | 工单状态机 + 前端时间线 |
| 异常发现与处置 | AIOps | Prometheus 指标 + 异常检测 + 工单自动生成（DocAI AIOps） |
| 自动化断点补齐 | 自动化中心 | 资产自动签收、巡检脚本（工具调用 Agent + checkpoint） |

## 六、三重转变（面试叙事升华）
1. 从「被动响应需求」→「主动挖掘痛点」：五大痛点来自一线走访，非拍脑袋。
2. 从「单一功能使用」→「系统方案设计」：从"做个功能"到"统一入口+目录+进度+自动化+AI"一体平台。
3. 从「关注技术实现」→「关注用户体验」：审计人员点选式、对话直达，外包可记录、运维可沉淀。

## 七、高保真 PC 原型（已交付，可交互）

> 文件：`prototype-PC-政务蓝白.html`（直接用浏览器打开）。前端可交互版见 Step 6 前后端开发产物（`static/index.html`，由 FastAPI 驱动）。

**设计语言（政务蓝白 · 简洁科技 · 新时代）**
- 主色：政务主蓝 `#1858c9` / 深蓝 `#0e3a8c`；科技青 `#22b8cf` / 亮蓝 `#38bdf8`。
- 白底卡片 + 细描边 + 轻阴影；顶栏 mesh 渐变 + 发光强调线；进度节点脉冲动画、监控迷你图表营造科技感。
- 顶栏标语「数字审计 · 智慧运维 · 新时代」，右下「数据飞轮」呼应领域优化闭环。

**页面结构（三栏，1440+ 宽）**
| 区域 | 内容 | 对应痛点 |
|---|---|---|
| 顶栏 | 品牌 + 导航（工作台/服务目录/智能问答/运维监控/知识库）+ 全局搜索 | 统一入口 |
| 左栏 | 服务目录：十类审计支持 + 三类运维，分组点选 | 痛点一（内外割裂）、痛点二（目录化） |
| 中栏 | ① AI 对话直达服务单入口（一句话生成工单 + 快捷 chips）② 工单进度卡片（4 节点 stepper，审批状态/责任人/一键联系）③ 智能监控 KPI ④ 高频服务点选网格 | 痛点二/三/四/五 |
| 右栏 | 待我审批 / 通知公告 / 数据飞轮 | 痛点三（审批直达）、算法优化闭环 |

> 该原型即 Step 4 文字线框（4.1~4.3）的可视化落地，五大痛点解法均已呈现。
