# 强化学习对齐（PPO → DPO → GRPO）讲解页

> 演示页：`/rl-alignment.html` · 后端：`GET /api/opt/rl-report`、`POST /api/opt/rl-run` · 仿真：`sft/rl_alignment.py`（纯 numpy/CPU，秒级可复现）

## 一、上下游关系：从 Pretrain 到部署优化是一条单向依赖链

对齐（Alignment）不是孤立环节，它依赖上游、流向下游：

1. **Pretrain（预训练）**：海量无标注语料 → Base Model。决定能力天花板（最上游）。
2. **SFT（监督微调）**：(指令, 回答) 数据集 → SFT Model。教会「遵循指令、规范格式」。
3. **Reward Model（奖励模型）**：人类偏好对 (chosen/rejected) → RM。Bradley-Terry 训练标量奖励，给回答打分。**PPO/GRPO 的在线奖励来源；DPO 不需要。**
4. **对齐（RLHF / DPO / GRPO）**：SFT Model + RM/偏好 → Aligned Model。**核心环节。**
5. **部署优化（本项目定位，最下游）**：蒸馏/INT8/剪枝/投机解码/Prompt Cache 把对齐好的模型低成本、高并发 serve 出来。

> 关键认知：**本项目落在最下游**——把上游对齐好的模型高效地部署到审计运维场景。对齐方法的选择（PPO/DPO/GRPO）影响的是「模型有多符合人类偏好」，而我们的优化层决定「它能不能便宜地跑起来」。

## 二、三种对齐策略：机制、优劣与适用场景

| 方法 | 模式 | 是否在线采样 | 额外模型 | 优点 | 缺点 / 风险 |
|---|---|---|---|---|---|
| **PPO (RLHF)** | 在线 RL | 需要 | policy/value/ref/RM（4 个） | 可在线探索、上限高、适配可验证奖励 | 训练不稳、显存大、超参敏感、工程复杂 |
| **DPO (2023)** | 离线偏好 | 不需要（纯离线数据） | ref 仅冻结（2 个） | 稳定、省显存、易复现、无 reward 循环 | 受静态偏好数据质量约束、无法探索新行为 |
| **GRPO (2024)** | 在线 RL | 需要（每 prompt 采 G 个） | 无 value（仅 policy+ref） | 去 value 网络（省显存）、适合 math/code 可验证奖励 | 每 prompt 多次采样、采样预算高 |
| **RLAIF** | 在线/离线 | 视实现 | RM 可由强模型生成 | 解决人类标注瓶颈、可规模化 | AI 反馈可能带偏、需校验 |

### 公式直觉
- **DPO 损失**：`L = -E log σ( β·[(logπ_θ(y_w|x)-logπ_ref(y_w|x)) - (logπ_θ(y_l|x)-logπ_ref(y_l|x))] )`
  —— 用「策略与参考策略的 logprob 差」构造**隐式奖励**，直接拿偏好对做分类式训练，绕开显式 RM 与 RL 循环。
- **PPO 裁剪代理目标**：`min( ρ·A, clip(ρ,1-ε,1+ε)·A )` + value 基线 + KL(ref) 惩罚；在线采样→RM 打分→更新。
- **GRPO 组内相对优势**：对同一 prompt 采样 G 个回答，优势 `A_i=(r_i-μ_g)/σ_g`，**无需 value 网络**。

## 三、可复现仿真（`sft/rl_alignment.py`）

在一张统一的 **2D 偏好分类测试台**上（特征 φ(x,y)=[x;y]，x=提示，y=候选回答；地面真值方向 w* 定义「什么是好回答」），真跑三种方法、训练同一类线性策略 π_θ，比较：

- **最终准确率**（越高越好）
- **收敛到 90% 的步数**（越少越快）
- **末段稳定性**（准确率标准差，越小越稳）
- **所需机制**（在线采样？额外模型？）

### 实测结论（确定性种子，可复现）

| 方法 | 最终准确率 | 收敛步数 | 稳定性(std) | 在线采样 | 额外模型 |
|---|---|---|---|---|---|
| DPO | **100%** | **3** | 0.0000 | 否 | ref 仅冻结 |
| GRPO | 92.5% | 5 | 0.0000 | 是(G=4) | 无 value |
| PPO | 85% | 15 | 0.0000 | 是 | value + ref + RM |

> 解读（诚实）：本玩具是**固定奖励的偏好分类**，DPO 正是为此而生，故收敛最快最稳；PPO 的在线探索优势在「可验证奖励」任务（数学/代码/工具调用）才真正发挥，本测试未充分激发，所以 85% 是其**地板而非天花板**；GRPO 通过去掉 value 网络，在「在线 + 轻量」之间取得折中。

## 四、关键结论（面试可直接讲）

1. **上下游关系**：Pretrain→SFT→(RM)→对齐(PPO/DPO/GRPO)→部署优化 是单向依赖链；越下游越贴近上线。本项目负责最下游的降本增效。
2. **DPO 用「离线偏好 + 隐式奖励」替代 PPO 的「在线 RL + 显式 RM + value」**，少两个模型、更稳更易复现；代价是无法在线探索、质量受偏好数据上限约束。
3. **GRPO 保留 PPO 在线探索，却用组内相对优势去掉 value 网络**，显存与工程更轻，适合可验证奖励，已被 DeepSeek-R1 验证。
4. **工程取舍**：追求稳定与低成本 → DPO；追求上限与可验证奖励 → GRPO/PPO；**推理优化层（蒸馏/量化/投机解码）对任何对齐产物都通用**，是「对齐之后」必做的降本增效。

## 五、与本项目其他优化线的关系

- 本页讲「模型如何更符合偏好」（训练侧 / 对齐侧）。
- `optimization.html` 讲「对齐好的模型如何更便宜地跑」（推理侧 / 部署侧）：蒸馏、INT8、剪枝、投机解码、企业级并行、Prompt Cache。
- 二者正交互补：**对齐决定模型「对不对」，优化决定「贵不贵、快不快」**。面试时可串成完整故事：先 RLHF 对齐，再蒸馏量化部署。
