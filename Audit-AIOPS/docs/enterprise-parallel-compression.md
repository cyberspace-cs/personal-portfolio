# 企业级并行（流水线 / 模型 / 上下文 / GPU 显存）+ 蒸馏压缩 —— 算法侧核心主线

> 本文把「**企业级并行 + 真实蒸馏压缩**」立为 Audit-AIOPS 算法侧的核心主线。
> 我们的五条优化线（蒸馏 / 量化 / 剪枝 / 投机解码 / 缓存）解决的是「**把模型做小、把推理做快**」；
> 而工业界要服务海量审计并发、把大模型塞进私有化低显存环境，还必须解决「**把小模型铺到多卡、把长上下文拆到多卡**」。
> 两者顺序固定：**先压缩、再并行**。

---

## 0. 为什么这是「核心」

单卡 fp32 的 7B 模型 ≈ 28GB 显存，根本无法满足企业私有化（单卡 24GB/16GB）与高并发需求。
真实企业落地只有两条路，且必须组合：

1. **压缩（降比特 / 降非零个数）** —— 本项目已真跑：蒸馏 + INT8 + 幅度剪枝。
2. **并行（张量 / 流水 / 上下文）** —— 把压缩后的模型铺到多卡，单卡显存与延迟同时可控。

> 面试定位：**不要只讲 toy 级「小模型能跑」，要讲清「小模型怎么在企业多卡环境低成本高吞吐地服务」** —— 这才是大模型推理开发的真问题。

## 1. 四类并行范式（与本项目仿真一一对应）

| 范式 | 一句话原理 | 本项目仿真 `sft/parallel.py` | 解决什么 |
|---|---|---|---|
| **模型并行 / 张量并行** | 权重列切到 N 卡，每卡算局部输出列，All-Gather 拼接；单卡参数降 1/N | `model_parallel()`：8 卡单卡参数比 **12.5%**，输出与单卡逐元素一致 ✓ | 单层太大放不进单卡 |
| **流水线并行** | 网络深度切 N 段，micro-batch 流水，降设备空泡 | `pipeline_util()`：深度12/微批16/4卡，利用率 25%→**84%（3.4×）** | 多层串行时设备大部分闲置 |
| **上下文并行 / 上下文压缩** | 长序列 KV 沿序列维切 N 卡，单卡只存 1/N，用时 All-Gather | `context_parallel()`：序列8192/KV维512，8 卡单卡 KV 比 **12.5%** | 超长上下文 KV 显存爆炸 |
| **GPU 显存并行利用** | 量化降比特 × 模型并行分权重 × 上下文并行分 KV | `memory_budget()` 组合预算表 | 单卡显存总账 |

### 1.4 组合显存预算（7B 级模型，序列 32768 / KV 维 4096，模型并行 4 卡 × 上下文并行 4 卡）

| 量化比特 | 单卡权重 | 单卡 KV | 单卡合计 | 对比 fp32 单卡 |
|---|---|---|---|---|
| INT32 (fp32) | 6675.7 MB | 128.0 MB | 6803.7 MB | 1× |
| **INT8** | 1668.9 MB | 32.0 MB | **1700.9 MB** | ↓4× |
| **INT4** | 834.5 MB | 16.0 MB | **850.5 MB** | ↓8× |

> 结论：**fp32 单卡 6.8GB → INT8+4×4 并行 ≈1.7GB/卡 → INT4+4×4 ≈0.85GB/卡**。
> 这正是「企业私有化低显存部署」的硬核证据：压缩 + 并行后，**单张 16/24GB 卡即可服务 7B 级大模型**，叠加本项目蒸馏/剪枝还能再降。

## 2. 核心范式：压缩在前、并行在后

```
① 压缩（本项目的真凭）
   蒸馏(Teacher软标签→小Student) → 量化(fp32→INT8/INT4) → 剪枝(幅度置零, 与量化正交)
        ↓ 体积/比特/非零个数 同时下降
② 并行（企业落地）
   模型并行(权重分片) × 流水并行(深度分micro-batch) × 上下文并行(长序列KV分片)
        ↓ 单卡显存↓ + 吞吐↑
③ 加速（推理期）
   投机解码(草稿并行校验, 无损) + 语义/Prompt缓存(高频命中跳过推理)
```

- **压缩与并行正交、可叠加**：剪枝降「非零个数」、量化降「比特」、并行降「单卡负载」——三者乘起来才是总收益。
- **先压再并的理由**：并行会增加通信/调度开销，模型越小，单卡算力越省、通信量越小，并行越划算。

## 3. 与本项目五条优化线的关系

| 本项目实测线 | 在「压缩+并行」主线中的角色 |
|---|---|
| 知识蒸馏 | 压缩起点：用 Teacher 软标签训小 Student，标注受限时精度不掉 |
| INT8 量化 | 压缩核心：per-channel scale，体积↓4×、0 掉点 |
| 幅度剪枝 | 压缩补充：降非零个数（与量化正交），98% 稀疏无损、50× 乘加削减 |
| 投机解码 | 并行期加速：Draft 提议 + Target 并行校验，**无损** 2.14× |
| 语义/Prompt 缓存 | 推理期加速：高频/近义命中跳过整次推理，成本归零 |

## 5. 面试镇场话术（可直接背）

> “我们的优化分两层。第一层是**模型压缩**：蒸馏把 Teacher 的暗知识迁给小 Student、INT8 量化把体积压 4×、幅度剪枝再砍掉冗余权重，三者正交可叠加，实测 98% 稀疏仍无损、单卡算力需求降 50×。
> 第二层是**部署并行**：压缩后的小模型用模型并行（权重分片，单卡参数 1/N）、流水并行（micro-batch 把设备利用率从 25% 提到 84%）、上下文并行（长序列 KV 切到多卡，单卡只存 1/N）铺到多卡。
> 组合下来，一个 7B 模型 fp32 单卡要 6.8GB，INT8 + 4×4 并行后单卡只要 1.7GB，再加投机解码和语义缓存，单卡就能低成本高吞吐服务审计高并发——这就是企业私有化落地的核心。”
