# 智能体研发路径 · 最佳实践（从 0 到可演示的面试弹药）

> 本文把 Audit-AIOPS 项目从立项到可演示、可面试的完整过程，提炼为一条**可复用的智能体研发路径**。
> 它不是概念清单，而是每一步都附带**做法、关键产物、最佳实践、易错点**的实战手册——直接照着走，就能把一个 Agent 平台从 0 做成「端到端真跑、零依赖可复现、面试现场能镇场」的亮点项目。

---

## 0. 元原则（贯穿全程的 6 条铁律）

这 6 条是后面所有阶段共享的「宪法」，任何一步偏离都会在项目后期付出代价：

1. **真实实现 > 概念**。所有优化（蒸馏/量化/剪枝/投机解码/缓存/对齐）必须端到端真跑、纯 numpy/CPU 秒级可复现，作为面试硬证据。「讲得出原理 + 跑得出数字」才是弹药。
2. **真实数据不编造**。用确定性种子生成大量贴合痛点的数据，问答全可回溯到原始记录；宁可标注「代理」也绝不幻觉。
3. **零外部依赖 / 纯 CPU 可复现**。演示不卡环境、不依赖外网密钥即可跑通（可插拔基座在 mock 模式默认全绿）。
4. **可插拔基座 + 优雅降级**。LLM / 视觉编码 / 视觉模型统一 env 门控，无密钥走 mock/代理，配密钥即升级真模型，服务永不中断。
5. **政务蓝白设计语言**（PC 端优先、简洁科技感）。统一主蓝 `#1858c9` / 科技青 `#22b8cf`，零外网 CDN，纯 CSS/canvas/SVG 绘图。
6. **文档 / 简历 / 面经 / 记忆 四同步**。每落地一条能力，立刻同步 README、docs、面试-优化技术面试题库、两份简历、面试准备总览、MEMORY.md，保证对外口径一致。

## 阶段一：定位与调研（先想清楚为谁做、做什么）

**目标**：把「我想做个 Agent」变成「为某类评估维度、解决某类痛点、用某套技术栈」的精准项目定位。

- **做法**
  1. 岗位/用户调研：列出目标岗位（如 DeepSeek/智谱/字节 + 混元/千问；三类岗：Agent 应用开发 / LLM 推理 / LLM 算法优化）。
  2. 项目-岗位映射：把每个岗位要的能力映射成项目模块，标注对口程度。
  3. 技术提取：读权威资料（面试攻略 / 技术白皮书 / 开源项目 README），用 PDF 提取 + 关键词过滤 + 章节窗口抽取，沉淀可复用点。
- **关键产物**：一句话项目定位 + 痛点清单 + 技术映射表。
- **最佳实践**：以「评估维度」倒推项目设计——面试官关注什么，就落地什么，别自嗨做用不上的功能。
- **易错点**：调研贪大求全。原则「只搜最典型案例，不要全量搜索」，调研从简、开发从实。

## 阶段二：产品与原型（把痛点变成信息架构）

**目标**：在写一行后端之前，先让所有人（包括你自己）对齐「系统长什么样、解决什么」。

- **做法**
  1. 痛点 → 需求映射：每个痛点对应一个需求，再对应一个信息架构模块。
  2. 信息架构：统一入口 / 服务目录 / 我的工单 / 自动化中心 / 知识库 / 角色视图。
  3. 高保真原型：先用 Visualizer 画 SVG 线框对齐认知，再生成政务蓝白 HTML 原型（顶栏品牌 + 左侧服务目录 + 中部对话直达 + 工单进度 + 监控 KPI）。
- **关键产物**：原型设计文档 + 可点击 HTML 原型。
- **最佳实践**：**先交互、后接后端**；PC 端优先、政务蓝白、科技感。用线框 SVG 快速对齐，避免直接美化导致返工。
- **易错点**：原型过度堆功能。每加一块都要能回扣一个痛点。

## 阶段三：平台开发调研与技术选型设计 + 前后端落地（最小可运行闭环）

> 这一阶段是用户最容易「直接开写」而跳过的一步。**先调研、再选型、后落地**——把"用什么、为什么"写清楚，既能指导开发、也是面试被问"为什么选 FastAPI / 为什么不用 React"时的镇场弹药。

### 3.0 平台开发调研（先想清楚用什么、为什么）

- **调研维度**：① 后端框架成熟度/异步能力/生态；② 前端是否需要构建链（演示项目重速度、轻工程化）；③ 基座可插拔性（能否无密钥先跑通）；④ 依赖体积与复现成本（能否纯 CPU、零外网）；⑤ 部署形态（单进程 vs 前后端分离）。
- **候选对比（本项目实际考量）**
  | 维度 | 候选 A | 候选 B | 本项目选择 | 理由 |
  |---|---|---|---|---|
  | 后端框架 | Django | **FastAPI** | FastAPI | 原生异步、Pydantic 类型即文档、轻量、适合 Agent API 服务 |
  | 后端服务 | Flask | **Uvicorn+FastAPI** | Uvicorn | ASGI 高并发、热重载、单机演示足够 |
  | 前端框架 | React/Vue | **原生 HTML/CSS/JS** | 原生 | 零构建、零 CDN、打开即跑、演示不卡环境；政务蓝白用纯 CSS/canvas/SVG 即可 |
  | 向量检索 | 只上 FAISS | **TF-IDF(零依赖)+FAISS(可选)** | 双路 | 先零依赖跑通，FAISS-CPU 作为可选增强 |
  | LLM 基座 | 绑死某厂商 | **Mock+混元/千问可插拔** | 可插拔 | env 门控，无密钥默认 Mock 全绿，配密钥即升级真模型 |
  | 存储 | Postgres | **JSON/JSONL 文件** | 文件 | 演示数据确定性种子生成、落盘即持久、零运维 |
- **调研结论**：演示型 Agent 平台应「后端重框架、前端轻构建、基座可降级、存储零运维」，把复杂度留在算法与检索侧，不在工程链上内耗。

### 3.1 后端技术选型（落地）

- **语言/运行时**：Python 3.13（managed 隔离 venv，numpy 等装隔离环境不污染系统）。
- **核心依赖**（`requirements.txt`）：`fastapi` + `uvicorn[standard]` + `pydantic` + `httpx`（调外部 LLM/健康检查）+ `python-multipart`（ASR 文件上传）+ `faiss-cpu`（可选向量召回）+ `numpy`（算法侧仿真）。生产可选：`sentence-transformers` / `funasr` / `peft` / `transformers` / `accelerate` / `datasets`（按 `EMBEDDING_BACKEND` / `ASR_BACKEND` 门控，默认不装）。
- **分层架构**：`app/{config, models, llm, agent, services, api, main}`
  - `config.py`：集中配置（app_name/version/cors_origins/llm_provider/各 backend 开关）。
  - `models.py`：Pydantic 模型（请求/响应/领域实体，向后兼容可选字段）。
  - `llm/client.py`：`LLMClient` 抽象——默认 Mock（关键词/模板），env 门控切混元/千问（OpenAI 兼容 `/chat/completions`）。
  - `agent/`：`orchestrator.py`（意图识别→拆单→审批路由→记忆，ReAct 式）+ `memory.py`。
  - `services/`：检索/运维/实验/技能/OA 等业务能力。
  - `api/`：路由模块（`routers` / `extra` / `experiments` / `ops`），按域拆分。
- **应用装配**（`main.py`）：`FastAPI(app)` + `CORSMiddleware` + 四个 router `include_router` + `StaticFiles(directory="static", html=True)` 挂载 `/`（前后端同进程、免跨域、免独立前端服务）。

### 3.2 前端技术选型（落地）

- **零框架、零构建、零 CDN**：纯 HTML + CSS + 原生 JS（`fetch` 调 API），`<style>` 内联 + 独立 `app.js`；图表用 **canvas / 内联 SVG** 手绘，不引图表库。
- **设计语言**：政务蓝白（主蓝 `#1858c9` / 深蓝 `#0e3a8c` / 科技青 `#22b8cf`），白底卡片 + 细描边 + 轻阴影，mesh 渐变与发光强调线营造科技感；PC 端优先。
- **工程约定**：所有页面走 `StaticFiles` 直托，URL 形如 `/`、`/optimization.html`、`/ops-console.html`；新增脚本用 `typeof api==='function'` 守护，单点失败不阻塞整页；依赖端点用 `setInterval` 轮询真实值（如状态条 30s 刷新）。
- **为什么不用 React/Vue**：演示项目追求「打开即跑、零依赖可复现、面试现场不卡构建」；纯原生反而更显工程克制与可控，且政务蓝白视觉完全够用。

### 3.3 基座与存储选型

- **LLM 基座**：可插拔三态——Mock（默认，关键词/模板，零密钥）→ 腾讯混元（`HUNYUAN_API_KEY`）→ 阿里千问（`QWEN_API_KEY`）；视觉编码同理（`VISION_PROVIDER` + proxy 代理降级）。统一 OpenAI 兼容接口，切换不改业务代码。
- **存储**：文件即数据库——`data/*.json` / `*.jsonl` 落盘（运维 `data/ops/ops_data.json`、实验 `data/experiments/records.jsonl`）；固定种子生成、重启不丢、零运维。

### 3.4 最小可运行闭环（落地顺序）

**目标**：打通「一句话 → 意图识别 → 拆单 → 审批路由 → 记忆」的端到端闭环，让系统先「活」起来。

- **做法**：先实现 `health` + `chat`（意图识别→拆单→审批路由→记忆）→ `catalog` / `workorders` / `monitor` / `knowledge`，前后端联调跑通一个闭环，再按路径后续阶段扩展。
- **关键产物**：可运行后端（8001）+ 工作台前端 + 基础 API。
- **最佳实践**：**先打通一个端到端对话闭环再扩展**；用端口约定文件（如 `port-claim-8000.txt`）避让并行伙伴，绝不互杀进程。
- **易错点**：模块循环导入。`cache.py` 与 `app.services` 循环时，把依赖内联成 `_local_embed` 解耦。

## 阶段四：检索增强（RAG 四路演进）

**目标**：把「问答」从「靠 prompt 硬编」升级为「带来源、可回溯」的检索增强，并逐级增强为四路混合。

- **演进路线**
  1. **① 关键词 TF-IDF 检索**（零依赖，中文 char-bigram 分词，无需向量库）。
  2. **② 混合检索**（TF-IDF + FAISS 向量 + RRF 倒数排名融合）。
  3. **③ 图 RAG**（吸收 LightRAG：审计实体共现图 + Low-level 具体实体/High-level 图 BFS 扩散双层检索，作为第三路并入 RRF）。
  4. **④ 多模态 RAG**（吸收 RAG-Anything：文本/表格/截图描述统一进检索，作为第四路）。
- **关键产物**：`retrieval_hybrid.py` + `knowledge-hybrid.html`（四路对比可视化）+ 各路报告端点。
- **最佳实践**：检索必须**可解释 + 可回溯**——标来源、标命中实体、标检索层（关键词/向量/图/多模态）。实体抽取先用**领域词典**替代 LLM，保证 CPU 可复现；视觉编码做成可插拔（proxy 代理 → 配密钥升级真 VLM）。
- **易错点**：盲目上向量库导致演示环境卡死。零依赖优先，把「真·视觉嵌入」留作可插拔升级项。

## 阶段五：推理优化（算法侧，全真跑）

**目标**：用真实实测数字证明「你懂大模型降本增效」，这是算法/推理岗的镇场弹药。

- **六条线（套路完全一致）**
  1. 知识蒸馏（Teacher→Student，+5pt）
  2. INT8 对称量化（3.95×、0 掉点）
  3. 幅度剪枝（98% 稀疏无损、乘加削减 50×，99% 起断崖）
  4. 投机/推测解码（2.14×、输出 100% 一致、无损）
  5. 语义/Prompt 缓存（省 ~800ms）
  6. Prompt 前缀 KV-Cache 强化（命中率 99.75%、TTFT↓87.7%、月省 ¥1496）
- **企业级并行（核心主线）**：模型并行 / 流水并行 / 上下文并行 + 压缩组合显存预算（范式：**压缩在前、并行在后**）。
- **标准工作流（每条线复用）**：
  `sft/xxx.py` 真跑 → 输出 `sft/data/xxx_report.json` → `app/api/extra.py` 加 `GET /api/opt/xxx-report` → `optimization.html` 加板块 + `loadXxx()` → 同步 docs/面经/简历/README/面试总览。
- **关键产物**：`sft/{distill_compress,quantize,prune,speculative,prompt_cache,parallel}.py` + 报告 + 九区块实验台页面。
- **最佳实践**：公共函数 `_load/_featurize/_train_softmax/_predict/_acc` 跨脚本复用；剪枝（降非零）与量化（降比特）**正交**，工程常「先剪枝再量化」；投机解码靠接受率提速且**无损**。
- **易错点**：混淆概念。蒸馏≠压缩（蒸馏是小模型学软标签）；KV cache 是推理缓存不是模型压缩。模型并行初版误用 `np.sum` 应 `np.concatenate(axis=1)`。

## 阶段六：Agent 工程能力沉淀

**目标**：把「能对话」升级为「能调动工具、能演进技能、能控成本」的生产级 Agent。

- **做法**
  1. 技能中心 `app/skills/registry.py`：领域技能注册表（触发意图 / 是否需审批 / 工具 / 版本 / 演进来源），编排层 `resolve_skills()` **零改动增删能力**，审批技能对齐双人审批。
  2. CLI-native OA 工具 `app/services/oa_mcp.py`：把 OA 操作封装为 CLI 式工具（如 `oa approval submit --type ukey`），每个带 schema + `cli` 命令模板，MCP-native。
  3. 两层缓存架构：服务端 prefix/KV cache（量化） + 应用层 精确/语义 响应缓存。
- **关键产物**：技能中心面板 + OA-CLI 原生工具面板 + 缓存端点。
- **最佳实践**：**Agent = Model + Harness（做薄）**；skill 进化（OpenSpace 哲学）；成本控制（黄超「自负盈亏」）；ToB 稳定（双人审批 + Checkpoint）。
- **易错点**：工具注册表与业务对象类型不一致（dict vs 对象）导致 count=0，用 `getattr` 兼容。

## 阶段七：真实数据驱动（运维落地，蓝鲸经验）

**目标**：用「真实大量数据 + 多用户智能体 + 不编造」把平台做厚，这是用户停留最久、最显价值的一层。

- **做法**
  1. 服务目录细化：以权威分类（十大审计技术支持 + 三大日常运维）为基准，**不另起炉灶**，扩展 SLA/自助化/监控指标/痛点/AI 价值字段。
  2. 真实数据引擎 `app/services/ops_data.py`：固定种子生成 148 工单 / 107 告警 / 50 变更，落盘 `data/ops/ops_data.json`。
  3. 多用户智能体：6 个 persona 各自承接工单/告警、自动化处置、CSAT，模拟多用户协作。
  4. 真实量化 KPI：ITSM（解决率/自动化率/SLA/MTTR/CSAT/FCR/重开率）+ 运维（在线率/告警收敛/自愈率/恢复时长）+ 变更双人审批率。
  5. 监控大屏接真实 ops 数据；痛点洞察由数据自动推导。
- **关键产物**：运维控制台 + 服务目录细化页 + 监控大屏（真实数据）+ 痛点洞察。
- **最佳实践**：参考成熟 AIOps（蓝鲸 BlueKing 的 CMDB/监控/ITSM/自愈；Observe→Engage→Act 三层；ITSM KPI 体系）。数据驱动 + 双人审批留痕（审计合规）。
- **易错点**：改了生成逻辑必须**重启 uvicorn 再 POST /seed**（运行进程内存里的旧模块不会变）；reseed 后数据已落盘，后续重启稳定加载。

## 阶段八：智能分析与强化学习对齐

**目标**：把「对齐」讲清楚上下游关系，并用统一测试台真跑 PPO/DPO/GRPO，体现算法深度。

- **做法**
  1. LLM 智能分析 `POST /api/ops/analyze`：始终先基于真实 KPI 生成接地分析；配真实密钥升级自然语言解读，Mock 优雅降级为结构化模板。
  2. RLHF 三方法 `sft/rl_alignment.py`：统一 2D 偏好分类测试台，训练同一类线性策略 π_θ，公平比较。
     - **DPO**：离线偏好 + 隐式奖励，2 模型，最稳最快（实测 100% / 3 步 / 稳定性 0）。
     - **GRPO**：组内相对优势去 value 网络，适合可验证奖励（92.5% / 5 步）。
     - **PPO**：在线 RL + value + ref + RM 四模型，上限高但最娇气（85% / 15 步，玩具静态奖励未激发其上限）。
  3. 上下游关系：用 SVG 画 `Pretrain → SFT → RM → 对齐 → 部署优化`，高亮「部署优化 = 本项目定位」。
- **关键产物**：rl-alignment.html（上下游图 + 对比表 + 仿真曲线 + 结论）+ rl-report/rl-run 端点。
- **最佳实践**：对齐落在最下游工程落地；**DPO 生产首选、GRPO 适合可验证奖励、PPO 上限高但娇气**。诚实标注 PPO 85% 是地板非天花板——这反而成为好面试点。
- **易错点**：写入报告用 `os.makedirs`/`os.path` 别忘了 `import os`（曾 500）。

## 阶段九：参赛叙事与价值升华

**目标**：把分散的能力串成一条主线，形成「可参赛、可演示、可讲价值」的成品。

- **做法**
  1. 科研实验记录 Agent（AdventureX 原型）：真实用户数据接入（上传 .md/.csv/截图 → 抽取 → 入库）+ 平台效果量化（records/entities/cross_links/duplicates/time_saved 随真实数据实时变）。
  2. 主页升级为平台控制台：实时状态条（30s 刷新真实值）+ 能力全景网格（带真实 KPI）+ AdventureX 参赛横幅。
  3. 叙事线：「真实数据 + 多用户智能体 + 不编造」一以贯之。
- **关键产物**：experiment-agent.html + index.html 控制台 + 参赛申请材料。
