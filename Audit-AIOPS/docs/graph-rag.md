# 图 RAG 检索增强（LightRAG 思路）· 技术文档

> 把港大黄超团队（HKUDS）**LightRAG** 的「图索引 + 双层检索」思想迁移落地到 Audit-AIOPS 的混合检索，
> 作为**第三路**并入既有 TF-IDF 关键词 + FAISS 向量的 RRF 融合，形成「关键词 / 向量 / 图」三层混合检索。
> 实体抽取用**审计领域词典替代 LLM 抽取**，换取纯 CPU / 零依赖 / 可当场复现，与本项目「轻量可复现」哲学一致（对标 MiniRAG）。

---

## 1. 为什么需要图 RAG

扁平向量 RAG（TF-IDF + FAISS + RRF）的短板：

- **只做「块级余弦」**，无法表达「审批流 → 责任人 → 资产 → 留痕」这类**实体间关系链**；
- 当用户问「Ukey 回收要哪些审批」时，纯关键词可能漏掉「数据安全与审计留痕」（它没出现「Ukey」二字，但同属「审批 + 双人 + 合规」关系簇）；
- 同义/长尾表述越多（审计领域尤甚），扁平召回越容易**召回不足或排序错乱**。

图 RAG 的解法：先抽**实体**、建**实体共现图**，再让检索沿图**扩散**，把「关系相关」的文档也召回。

---

## 2. LightRAG 思想回顾（我们要迁移的）

| LightRAG 原版 | 本项目的轻量落地版 |
|---|---|
| Graph Index：LLM 抽取 (实体, 关系, 描述) 建图 | **审计实体词典抽取**（17 个领域实体），建实体共现图 |
| Low-level 检索：具体实体 + 其邻居（向量检索实体描述） | **Low-level**：查询实体直接命中的文档（强相关） |
| High-level 检索：跨实体的抽象关系 / 主题（图遍历） | **High-level**：沿图 BFS 扩散 2 跳，召回关联实体/文档 |
| 图检索结果 + 原始 chunk 融合喂 LLM | 图路排名与关键词/向量 **三路 RRF 融合** |

> 取舍说明：原版用 LLM 抽取实体/关系，质量高但需模型、慢、难复现；本项目用**领域词典**抽取，
> 在审计这种**实体封闭、术语规范**的场景下召回足够，且 100% 可当场复现——面试讲清这个取舍本身就是加分点。

## 3. 本项目落地（架构）

```mermaid
graph LR
  Q[用户查询] --> EX[审计实体抽取<br/>AUDIT_ENTITIES 词典]
  EX --> KW[① 关键词召回<br/>TF-IDF]
  EX --> VEC[② 向量召回<br/>FAISS]
  EX --> GR[③ 图 RAG 检索<br/>GraphRAGRetriever]
  GR --> LOW[Low-level<br/>具体实体命中]
  GR --> HIGH[High-level<br/>图 BFS 扩散 2 跳]
  KW --> RRF[RRF 融合<br/>k=60]
  VEC --> RRF
  GR --> RRF
  RRF --> OUT[混合命中 Top-K<br/>+ 图素材(实体/边)返回前端]
```

核心代码位置：`app/services/retrieval_hybrid.py`

- `AUDIT_ENTITIES`：审计领域实体词典（归一名 → 命中别名，含同义归一），共 17 个（审批/拆单/权限/Ukey/工单/留痕/合规/资产/巡检/监控/服务目录/对话直达/数据飞轮/双人审批/催办/视频会议/回收）。
- `extract_entities(text)`：确定性子串匹配抽取实体，无需模型。
- `GraphIndex`：构建实体共现图——`entity_docs`（实体→文档）、`adj`（实体→共现邻居，权=共现文档数）。
- `GraphRAGRetriever`：Low-level（直接命中）+ High-level（图扩散），并标注每条命中的「直接实体 `entities`」与「经图扩散关联实体 `via`」、`layer`（low/high）。
- `HybridRetriever(enable_graph=True)`：把图路并入 RRF，向后兼容（默认 `enable_graph=False` 仍是两路）。

## 4. 实测数据（由 `python sft/graph_rag.py` 生成 `sft/data/graph_rag_report.json`）

**图规模**：17 实体 / 108 条共现边 / 平均度 9.88 / **中枢实体「审批」**（连接度最高）。

**双层检索 vs 纯关键词（6 条样例查询）**：

| 查询 | 纯关键词命中 | 图 RAG 命中 | 图扩散多召回 |
|---|---|---|---|
| Ukey 制作后怎么回收？需要哪些审批 | 3 | 6 | +3（含「数据安全与审计留痕」「终端领用与维修」等关联文档） |
| 资产领用后如何巡检和签收 | 3 | 5 | +2 |
| 审批流怎么自动拆单并路由责任人 | 3 | 6 | +3 |
| 怎么监控异常并自动生成工单 | 3 | 5 | +2 |
| 数据飞轮怎么驱动 SFT 优化模型 | 3 | 5 | +2 |
| 权限变更为什么需要双人审批和留痕合规 | 3 | 6 | +3 |

- **6/6 查询均有图扩散多召回增益**，平均多召回 **2.33 篇**。
- 多召回的文档正是「同关系簇但未出现查询词面」的关联知识——这正是图 RAG 相对扁平向量 RAG 的价值。

**样例：查询「Ukey 制作后怎么回收？需要哪些审批」**
- 命中实体：`['Ukey', '回收', '审批']`
- 图扩散关联实体（2 跳）：`['催办','双人审批','合规','对话直达','巡检','工单','拆单','数据飞轮','服务目录','权限','留痕','监控','视频会议','资产']`（共 14 个）
- 共现边：以「审批」为中枢向外扩散的 14+ 条边，直观呈现审计知识的关系网络。

## 5. 面试要点：图 RAG vs 向量 RAG（避免混淆）

- **向量 RAG**：块级语义相似，擅长「字面不同但意思近」；不擅长「关系链推理」与「实体关系召回」。
- **图 RAG**：在向量 RAG 之上加**实体关系结构**，擅长「沿关系链扩散召回关联知识」与「可解释的实体路径」。
- 二者**不是替代而是互补**：本项目是「关键词 + 向量 + 图」**三路融合**，用 RRF 规避分数量纲。
- **实体抽取选型**：LLM 抽取（LightRAG 原版，质量高、需模型）vs 领域词典（本项目，零依赖、可复现）——审计实体封闭，词典版够用且可当场演示，面试讲清取舍。

## 8. 多模态 RAG 扩展（RAG-Anything 思路，同源迁移）

图 RAG 解决「实体关系链」，而 **RAG-Anything** 解决「多模态统一进 RAG」——审计文档常含表格（资产台账、权限变更表）与截图（Ukey 制作界面、留痕界面）。两者同源：都是「在文本 RAG 之外，给检索增加结构化 / 多模态信号」。

本项目在 `retrieval_hybrid.py` 加 `MultimodalRetriever`：

- 把每篇文档附带的「表格结构化文本 / 图像描述文本」作为多模态元数据（审计领域内置样本已含 Ukey 制作截图、权限变更审批表、资产台账、审计留痕截图等）；
- 复用既有关键词 / 实体检索对多模态元数据做跨模态召回，命中时返回 `modalities`（image / table）与 `multimodal_hits`；
- 端点 `/api/knowledge/multimodal`，演示页 `/knowledge-hybrid.html` 多模态区块。

取舍：真实视觉嵌入需接多模态大模型（腾讯混元多模态 / 千问-VL）对图像 / 表格做跨模态编码；本环境无视觉模型，以「描述文本 + 结构化文本」代理，零依赖、可当场复现，复现 RAG-Anything「any modality 统一进 RAG」的核心思想。

> 图 RAG + 多模态 RAG 共同构成「向 HKUDS 迁移学习」的检索侧双翼：图 RAG 处理实体关系（LightRAG），多模态 RAG 处理表格 / 图像（RAG-Anything）。
