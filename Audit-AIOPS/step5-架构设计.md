# Step 5：整体架构设计

> 目标：把 Step 4 的产品能力映射为 **Agent 编排层 / LLM 推理层 / 数据处理层 / 业务层** 四层职责，明确各层边界、模块与技术栈，并给出「一次对话直达工单」的端到端调用链。横切关注点：**安全合规（审计留痕/权限/加密）** 与 **可观测性（日志/指标/Trace）**。

```
┌──────────────────────────────────────────────────────────────────────────┐

└───────────────────────────────────┬──────────────────────────────────────┘

                                     │  调用工具 / 查询 / 写入
```

## 二、各层职责与模块

### 1. 业务层（Business Layer）
| 模块 | 职责 | 关键设计 |
|---|---|---|
| 服务目录 | 13 项服务（10 类审计支持 + 3 类运维）分类、点选式提交 | 按角色呈现视图，解决「内外割裂」 |
| 工单系统 | 工单 CRUD、状态机、进度卡片数据 | 状态：提交→拆单→审批→执行→完成 |
| 审批流引擎 | 按事项自动拆分多审批流并路由责任人 | 对应「痛点二」自动拆单 |
| 监控告警 | 指标采集、异常检测、自动生成工单 | AIOps：异常→工单（痛点五） |
| 知识库 | 运维/制度文档 RAG 检索与问答 | 多路检索 + 引用溯源 |
| 用户/权限 | 审计/运维/外包三角色，最小权限 | 解决「内外割裂」 |

### 2. Agent 编排层（Orchestration Layer）—— 项目核心卖点
| 模块 | 职责 | 技术映射（Step 3） |
|---|---|---|
| 意图识别 Agent | 把自然语言/语音转成结构化诉求 + 服务项映射 | DocAI PlanExecute / pico 编排 |
| 规划/拆单 Agent | 将复合诉求拆为多条子工单 + 各自审批链 | 规划 Agent（面试攻略 ReAct 规划） |
| 审批路由 Agent | 依据服务目录的 approval_chain 路由责任人 | pico 工具网关 + 高风险审批 |
| 执行 Agent | 调用工具/MCP 完成发放、签收、巡检 | MCP + 工具调用（pico） |
| 记忆系统 | 短期对话上下文 + 长期用户/工单画像 | pico 结构化记忆 + checkpoint |
| 工具网关/MCP | 统一接入 OA/审批/CMDB/邮件/资源系统 | pico 统一工具网关 + MCP |

> **范式**：ReAct（Thought→Action→Observation 循环）+ Reflection（结果反思重试）+ Checkpoint（断点续办，解决「自动化断点」）。

### 3. LLM 推理层（Inference Layer）
| 模块 | 职责 | 技术栈 |
|---|---|---|
| 双基座接入 | 腾讯混元 / 阿里通义千问（OpenAI 兼容接口） | vLLM / SGLang 私有化部署 |
| RAG Serving | 向量 + BM25 + RRF 混合检索 → 重排 → 引用溯源 | Redis / Milvus + Rerank |
| 领域优化闭环 | 审计术语 SFT + 事实核查 + 评测对齐 | 数据飞轮（工单/评价回流） |
| 推理优化 | 量化、批处理、KV 缓存、流式输出 | vLLM / SGLang |

### 4. 数据处理层（Data Layer）
| 模块 | 职责 | 技术栈 |
|---|---|---|
| 观测数据 | 指标/日志/链路采集与异常检测 | Prometheus + ELK + OTel |
| 主数据 | 设备/帐号/权限 CMDB | 关系库 / ES |
| 文档 ETL | 分块→Embedding→向量库 | LangChain ETL + 向量库 |
| 样本存储 | 工单/评价回流，驱动 SFT/评测 | 对象存储 / 数仓 |

## 三、端到端调用链（一次「对话直达工单」）

```
审计人员(Web/企微)
  │ "我要借终端开视频会并连因特网"
  ▼
[接入层] 统一对话入口
  ▼
[Agent 编排层]
  意图识别 Agent ──→ {terminal, meeting, network}
  规划/拆单 Agent ──→ 3 条子工单，各自 approval_chain
  审批路由 Agent ──→ 责任人 + 并行/串行审批
  记忆系统       ──→ 写入工单画像（用户/历史）
  ▼
[LLM 推理层]
  · 调用混元/千问 生成工单摘要 + 字段抽取
  ·（知识问答时）RAG Serving 检索并重排、附引用
  ▼
[业务层] 工单系统创建 WO-xxx，进度卡片初始化
  ▼
[数据处理层] 指标/日志落盘；评价回流样本库（数据飞轮）
  ▼
返回：进度卡片 + 一键联系责任人 + SLA 倒计时
```

## 四、技术栈清单（面试呈现，已实现口径）

| 层 | 技术 | 说明 |
|---|---|---|
| 接入/前端 | HTML/CSS/JS（政务蓝白原型）、FastAPI 静态托管 | PC 端优先 |
| 业务/服务 | **FastAPI** + Pydantic + 内存/关系存储 | 本仓库已落地可运行 Demo |
| Agent | LangGraph（规划/记忆/工具）+ MCP | 编排层核心 |
| 推理 | 混元/千问（OpenAI 兼容）、vLLM/SGLang | 私有化部署 |
| RAG | 向量库(Milvus/Redis) + BM25 + RRF + Rerank | 多路检索 |
| 数据 | Prometheus + ELK + OTel | AIOps 观测 |
| 横切 | 审计留痕、最小权限、HTTPS/加密 | 安全合规 |
