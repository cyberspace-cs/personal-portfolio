## ⭐ 算法侧一句话镇场（面试主动抛）
> "算法侧优化我没停在概念——五条压缩线全部真跑通、可当场复现：①蒸馏：小模型仅 42 条标签时 95%，用 Teacher 软标签蒸馏回 100%（+5pt）；
> ②INT8 量化压 3.95× 且 0 掉点；③剪枝：98% 稀疏仍无损、乘加削减 50×；④投机解码：草稿接受率 39.5%、2.14× 无损加速；⑤语义缓存二次命中省 800ms。
> 端到端 Teacher→INT8 学生 63× 体积、10.8× 提速、100% 精度保持。
> **更关键的是企业落地主线——压缩在前、并行在后**：我把压缩后的小模型用模型并行（单卡参数 1/N）、流水并行（利用率 25%→84%）、上下文并行（长序列 KV 1/N）铺到多卡，7B 模型 INT8+4×4 并行单卡只要 1.7GB（fp32 要 6.8GB），这正是企业私有化低显存部署的核心。
> 全部纯 numpy / CPU 秒级，`python sft/distill_compress.py && python sft/prune.py && python sft/speculative.py && python sft/parallel.py && python sft/graph_rag.py` 复现。详见 `面试-优化技术面试题库.md`、`docs/enterprise-parallel-compression.md` 与 `docs/graph-rag.md`。
> 检索侧我也做了升级——吸收港大黄超团队 LightRAG 的「图索引+双层检索」，把审计实体共现图作为第三路并入 RRF，6/6 查询都有图扩散多召回（平均 +2.33 篇），这正是图 RAG 相对扁平向量 RAG 的优势，也是我向 HKUDS 迁移学习的最高价值落地项。
> 我顺着同一思路做了**多模态 RAG（吸收 RAG-Anything）**——把文档里的表格/截图也纳入统一检索，一张表、一张图也能被召回；视觉编码层我做成了**可插拔**：默认用预撰写描述代理（等价于 VLM 预期输出，零依赖可复现），生产上配混元视觉 / 千问-VL + 真实截图就切换成真·视觉嵌入，响应带 `encoder_mode` 标记、降级透明；并呼应黄超「成本控制·自负盈亏」，在实验台加了单轮 token 成本计算器：纯 Teacher(API) 单轮 ¥0.042，经蒸馏+INT8+投机+缓存优化后降到 ¥4.9e-5，月调用 500 万次可省约 99.9%。
> 更进一步，我把黄超团队剩下的高价值项也全落地了：**Prompt 前缀 KV-Cache 强化**（吸收 nanobot，长稳定系统前缀复用 prefill KV，命中率 99.75%、TTFT↓87.7%、月省 ¥1,496 prefill，与 cache.py 构成两层缓存）和 **Agent 技能中心**（吸收 OpenSpace「skill 进化」——能力沉淀为可演进 skill 注册表，编排层零改动即可增删，审批技能强制双人审批）。至此向 HKUDS/nanobot 迁移学习的 P0/P1/P2 全部落地。"

## 一句话记忆锚点
> 这个项目不是"套壳调 API"，核心资产在 **Agent 编排（把事办成，Model+Harness 做薄）+ 混合检索（关键词/向量/图 RAG/多模态 RAG 四路融合，事实可溯源、关系可扩散）+ 推理加速（缓存/量化/蒸馏/剪枝/Prompt 前缀 KV-Cache，成本可控可私有化）+ 企业级并行（压缩在前、并行在后，低显存多卡服务）+ Agent 技能中心（能力沉淀为可演进 skill，编排层零改动增删）+ CLI-native OA 工具层（把外部系统接进 Agent 的正确姿势，CLI-Anything）**。向港大黄超团队(HKUDS)/nanobot 迁移学习的 P0/P1/P2（图 RAG / 多模态 RAG / 成本控制 / prompt cache / skill 沉淀 / CLI-native）已全部落地。
> 面试就围绕这三条主线展开，遇到任何深挖都能回扣；Agent 哲学吸收港大黄超团队(HKUDS)/nanobot 的「做薄 harness、CLI 原生、skill 进化、成本控制、ToB 生产级稳定」，并把 LightRAG 图 RAG 已落地为检索侧第三路、RAG-Anything 多模态 RAG 已落地为检索侧第四类信号，呼应黄超「成本控制」在实验台加了单轮 token 成本计算器。
