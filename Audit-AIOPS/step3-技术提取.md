## 二、可复用技术方案清单（按能力域）

### 2.1 Agent 编排层
- **编排范式**（面试攻略 + DocAI 共识）：`Agent ≈ LLM + Planning + Memory + Tools`；不追求单一全能 Agent，而用"调度层 + 执行编排层"两层架构。
- **多 Agent 协作**：参考面试攻略的企业平台——编排器下挂 `ReAct Agent`（思考-行动-观察）、`规划 Agent`（任务分解）、`RAG Agent`（知识检索生成）、`反思 Agent`（质量校验）。DocAI 用 `ChatReAct / PlanExecute / KnowledgeIndex` 三态，职责分离、避免 God Class。
- **规划-执行**（Plan-and-Execute）：复杂任务先 LLM 粗粒度 Plan，每步内部用 ReAct 执行；关键路径用确定性工作流、非关键路径让 Agent 自主决策（pico 设计哲学，最契合"审批流确定 + AI 灵活"的审计场景）。
- **可复用技术点**：状态机驱动（替代 if-else 散落）、并发与超时（工具调用全链路带 timeout）、停机条件（final answer / step limit / retry limit）、父子 run 关系建模（多 Agent 时单独建模）。

### 2.2 记忆与上下文（直接对口"进度卡片/长期记忆/用户画像"）
- **分层上下文预算**（pico，强推荐复用）：把上下文拆成 `稳定背景 / 工作记忆 / 相关记忆 / 过程历史 / 当前请求` 五段，每段有预算；预算不足时按优先级收缩——先收相关记忆、再收历史、最后才动稳定背景，**当前请求永不裁剪**。prompt 长度【参考·可对标】6964→5418。
- **结构化记忆**（pico）：任务摘要 / 文件摘要 / 过程笔记 / 相关记忆召回分层；长期记忆只沉淀稳定事实（用户偏好、项目约定、关键决策），不让长期记忆变成冗长日志；带 freshness 校验与失效识别，避免"用旧状态继续推理"。【参考·可对标】重复读文件 60 次→0 次，follow-up 工具步数 1.0→0。
- **记忆工程要点**（面试攻略）：摘要压缩、引用溯源、记忆冲突解决、权限与隐私；显式记忆（用户确认保存）vs 隐式记忆（系统自动提炼）；情景记忆 vs 语义记忆。
- **对本项目映射**：短期记忆 = 当前工单/会话上下文（Redis 滑窗）；长期记忆 = 审计人员画像、服务目录、历史工单知识（向量库）；checkpoint = 工单断点续办。

### 2.3 工具调用与 MCP（直接对口"审批流/自动化/统一入口"）
- **统一工具网关**（pico，强推荐复用）：所有工具调用先过一层执行网关——检查工具是否存在、参数是否合法、**是否重复调用**、**是否越权、是否需审批**，再真正执行；执行结果回写 history / working memory / trace / checkpoint。
- **高风险审批策略**：不按工具名绑定，而按"运行模式 + 参数内容"绑定；高风险动作（如写文件、改配置、发邮件）走审批，参数校验不把模型输出当可信输入。
- **MCP 协议**（面试攻略 + DocAI）：Anthropic 推动的开放标准，"AI 侧 USB-C"，一次实现 Server 多端复用；pico 演进路线——`重构工具注册 → 加 skill registry → 接 MCP tool provider`，复用现有审批/trace/timeout。
- **工具编排**：串行（Pipeline）/ 并行（LLM 每步决定下一步）；失败兜底：Top-K 调大、混合关键词打分、LLM 二分类"是否适用"、允许用户澄清。

### 2.4 RAG 知识库（直接对口"运维知识问答/审计人员一线服务"）
- **端到端流程**（DocAI + 面试攻略）：文档解析（PDF/Word/iText/POI）→ 切分（`chunk_size=500, overlap=100`，保留前后缀）→ Embedding → 存储 → **混合检索（向量 + BM25）+ 重排** → LLM 生成（要求标注引用来源）。
- **多路检索**（面试攻略企业平台）：向量 + BM25 + 结构化查询，RRF 融合；精确编号查询（如"工单号 WO-xxxx"）纯向量检索很差，必须混合关键词。
- **Embedding 选型**：参考用 dashscope `text-embedding-v4`（1024 维）/ `bge-large-zh` / `all-MiniLM`；本地化部署避免数据泄露（**审计政务场景强约束**）。
- **向量存储**：Redis（中小规模暴力余弦相似度，部署简单）或 Milvus（千万级 HNSW/IVF）。本项目审计数据量中等，可先用 Redis Stack VSS，预留迁 Milvus。
- **增量同步与版本控制**（DocAI）：文档更新只处理变化部分；版本元信息（isCurrent）支持回滚；TTL 清理过期知识——直接对口"审计制度文档频繁更新、需可追溯"。
- **防幻觉**：所有回答基于检索片段、标注引用 `[参考1]`、检索相关性低（rerank<0.4）直接回"知识库暂无相关信息"；Self-Consistency 三次生成不一致标低置信度（面试攻略）——**直接对口我们的"事实核查/引用溯源"补强项**。

### 2.5 评测与治理闭环（直接对口"LLM 算法优化补强项"）
- **评测分层**（pico，强推荐复用）：harness regression / 上下文治理（prompt 长度、压缩率）/ 记忆收益（重复读次数、工具步数）/ 恢复正确性（恢复成功率、workspace 漂移识别率、误信旧状态）。
- **评测与审计闭环**：trace（每轮 prompt 怎么组、模型何时调、输出解析成什么、工具有没有失败）、report、task state 三者齐备，才能定位"上下文污染 / 动作失败 / 状态漂移 / 模型瞎推理"。
- **对本项目映射**：把"审计术语 SFT + 事实核查评测"做成独立评测集（审计问答准确率、引用命中率、幻觉率），形成"数据-训练-评测"证据链，覆盖第三类岗位。

### 2.6 监控与 AIOps（直接对口"智能监控/异常检测"）
- **指标监控栈**（DocAI）：Prometheus + Grafana + 自定义 AIOps MonitoringService；采集节点（node-exporter）、容器（cadvisor）、业务指标（AI 请求数 `ai.request`、错误数 `ai.errors`、响应时间、工单量、异常事件）；健康端点 `/health`；异常自动预警。
- **异常管控**：服务可用性检测、容器健康、故障检测；内部 MQ 告警，可扩展。
- **对本项目映射**：把"计算存储设备/应用系统/基础软件平台"三类运维指标接入 Prometheus，做异常检测（指标突增/突降、链路错误率）、根因分析，工单自动生成——直接对口痛点五"运维事件智能发现和处置空白"。

### 2.7 安全、审批与合规（强监管必含，建议补入映射表）
- **工具边界治理**（pico）：参数校验、工作区隔离、高风险审批、重复调用拦截、敏感信息脱敏、partial success 识别。
- **权限与留痕**（DocAI + pico）：文档/服务按用户·部门绑定权限；所有工具调用留审计日志（谁、何时、调了什么、审批与否）；强 RAG 溯源、禁止无引用断言（面试攻略企业落地三件套：强 RAG 溯源 / 模板化答复 / 未知转人工）。
- **对本项目映射**：审计场景天然需要"操作可审计、责任可追溯"，把审批流、工单流转、AI 操作全部落审计日志——既是合规要求，也是面试差异化亮点。

## 三、可直接复用的"亮点证据"模板（面试叙事用）

> 下列为参考材料中的可对标设计，落地时换成本项目真实数据即可讲出深度：

1. **编排层**：用户请求 → 意图识别 → Agent 编排器 → {对话 Agent / 规划 Agent / RAG Agent / 反思 Agent}；关键路径确定性工作流（审批）、非关键路径 Agent 自主决策。
2. **上下文预算**：五段式分层 + 优先级收缩，当前请求永不裁；参考压缩率 22%（6964→5418）。
3. **结构化记忆**：分层记忆 + freshness 校验，参考重复操作 60→0 次；支撑审计人员"下次接着办"。
4. **工具网关 + 高风险审批**：统一边界、重复调用拦截、参数级审批，直接落地"分散入口→统一入口、服务目录化、自动拆分审批流"。
5. **多路 RAG + 引用溯源**：向量+BM25+RRF 重排，回答标注来源、低相关拒答；参考 P95 420ms、可用性 99.95%、多轮完成率 89%。
6. **AIOps 监控**：Prometheus+Grafana 自定义指标，异常自动告警、工单自动生成。
7. **评测闭环**：上下文治理 / 记忆收益 / 恢复正确性 / 幻觉率 分层量化，形成可复盘证据链。
