# 面试现场演示脚本（5–8 分钟）

> 目标：用最短时间让面试官记住「审计领域 + Agent 编排 + RAG + 双基座」的差异化项目。
> 前提：平台已在本地 `http://127.0.0.1:8000` 跑起来（Mock 基座，无需联网）。

---

## 0. 开场 Elevator Pitch（30s）

> 我做了一个面向**审计领域**的智能一体化运维平台助手。审计人员办运维服务时最大的痛点是「入口分散、流程黑盒、自动化断点、没 AI 赋能」。我用 **Agent 编排 + 大模型（混元/千问可插拔）** 把它们一站式解决，把强监管强流程的政务场景作为护城河——不是玩具级 Chatbot。

**操作**：打开 `http://127.0.0.1:8000/`，展示政务蓝白工作台。

---

## 1. 痛点引入（40s）

> 真实业务里有五个痛点：①系统只给运维自己用，审计人员不知道能办什么；②入口分散，借终端开会联网要分别审批；③工单提交后像黑盒，不知卡哪、找谁；④资产领用线上申请线下签收；⑤缺乏 AI，反复电话问询。
> 我的三重转变：从被动响应 → 主动挖痛点；从单功能 → 系统方案；从技术实现 → 用户体验。

**操作**：指工作台右侧「通知公告 / 数据飞轮」，讲「数据飞轮」对应领域 SFT 评测闭环。

---

## 2. 演示 1：对话直达服务单（一句话拆单）（90s）

> 这是最核心的能力。用户一句话，Agent 自动判别多个事项、拆成多张审批单、分别路由责任人。

**操作**：在 AI 输入框输入：
```
我要为审计三组开通远程邮件帐号，容量 5GB，并借用一台会议终端
```
点「生成服务单」。展示：
- 识别到 3 类意图（邮件 / 终端 / 会议）
- 自动生成工单，进度卡片出现 4 个节点
- Toast 提示工单号

**话术**：「注意这里不是简单的关键词匹配——是意图识别后映射到服务目录白名单，再按事项独立拆单并行审批；不在目录里的诉求会转人工，避免瞎拆单。」

---

## 3. 演示 2：工单进度卡片（40s）

> 以前工单像黑盒。现在每个节点状态、责任人、预计耗时一目了然，还支持一键直达责任人催办。

**操作**：指中栏「工单进度卡片」4 节点 stepper（脉冲动画表示进行中）。点右侧「待我审批」的「审批」按钮，演示节点推进。

---

## 4. 演示 3：RAG 知识库问答（60s）

> 知识问答用检索增强，杜绝幻觉：先检索再生成，答案必须带来源。

**操作**：切到右侧「知识库问答」卡片，输入：
```
审批流是如何自动拆分的？
```
展示检索命中（带相似度分数）与来源标注。

**话术**：「检索层用 TF-IDF 关键词召回，已预留向量召回（混元/千问 embedding）做混合检索；生成层强制『仅依据上下文、标注来源』，上下文不足就如实拒答转人工。」

---

## 5. 演示 4：智能监控大屏（40s）

> 运维底座用 Prometheus + 异常检测，异常自动生成工单。

**操作**：打开 `http://127.0.0.1:8000/monitor.html`，展示 KPI（异常事件 ↓40%、自动处置率 86%、P95 420ms）与趋势图。

---

## 6. 收尾：岗位匹配 + 反问（30s）

> 这个项目最对口 **AI Agent 应用开发**：Agent 编排、工具调用、记忆、多 Agent 协作都有落地；也覆盖 **LLM 推理**（可插拔基座、RAG serving）；并用数据飞轮补强 **LLM 算法优化**（SFT + 评测对齐）。

**操作**：打开 `step6-简历亮点.md` 作为备查。

## 备用问答（被追问时）

- **Q：没 GPU/模型怎么演示？** A：基座可插拔，Mock 跑通编排，配 Key 即切真实生成——这正体现编排与推理解耦。
- **Q：怎么防 Agent 越权？** A：三层约束——服务目录白名单、敏感操作双人审批留痕、工具网关高风险需人工确认 + Checkpoint 恢复。
- **Q：RAG 怎么防幻觉？** A：检索增强 + 来源必标注 + 不足拒答；预留事实核查评测闭环量化防控。
- **Q：为什么选审计场景？** A：强监管是 Agent 落地的高压测试场，能跑通即证明企业级可用性，是护城河。
