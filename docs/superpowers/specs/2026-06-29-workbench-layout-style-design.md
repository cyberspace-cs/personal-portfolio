# 工作台布局原型页视觉升级设计（方案 A）

## 背景与目标

当前原型页用于比较“同一套顶部语义框 + 待办/工单聚合”的信息架构下，不同中部布局的呈现方式。用户已选择采用方案 A（左右分栏），并希望“最重要的是把风格变漂亮点”，且整体方向为“政务/国企蓝”，信息密度“适中”。

目标：
- 在不改变信息架构与文案含义的前提下，让页面呈现更专业、更稳重、更统一，适合审计/工单场景。
- 提供两套可切换的“政务蓝”皮肤（偏深蓝 / 偏灰蓝），便于快速对比并定稿。

非目标：
- 不引入外部 UI 框架或在线资源依赖（保持页面可离线直接打开/本地预览）。
- 不实现真实业务交互与数据联动（仅原型表现与交互反馈）。

## 范围

覆盖页面：
- `.superpowers/brainstorm/10205-1782701726/content/layout-1.html`

改动类型：
- 补充完整 HTML 文档结构与资源组织（head/body、样式、脚本）。
- 增加内联 CSS（或同目录 CSS 文件，若需要分离）与少量交互脚本（A/B 选中态、皮肤切换）。
- 调整现有结构的 class 与少量布局包装（不改文案、信息结构与示例数据内容）。

## 视觉方向

整体：政务/国企蓝 + 适中信息密度。

设计原则：
- 稳重与可读性优先：字号层级清晰、对比度足够、边界明确。
- 结构秩序感：区块标题、分组、间距节奏统一。
- 低装饰：阴影克制、圆角适中、避免高饱和大面积色块。

## 皮肤（Theme）方案

通过 CSS 变量实现两套皮肤，默认展示其一，并提供切换控件：

### 皮肤 A：深政务蓝（Blue-Deep）
- 主色：更深、更权威（用于选中态、主按钮、重点强调）。
- 适用：更正式的内网系统、审计/风控后台的常见视觉。

### 皮肤 B：灰政务蓝（Blue-Gray）
- 主色：更偏灰蓝、对比更柔和（降低刺眼感）。
- 适用：长列表浏览、阅读时间较长的工作台。

切换方式：
- 页面顶部提供一个简洁的“皮肤切换”控件（两段式 Segmented Control 或两按钮）。
- 切换仅改变 CSS 变量，不改变 DOM。

## 设计令牌（Design Tokens）

以 CSS 变量为单一事实来源，建议令牌分层：

- 颜色：`--bg`, `--surface`, `--surface-2`, `--text`, `--text-muted`, `--border`, `--primary`, `--primary-weak`, `--danger`, `--success`
- 排版：`--font-family`, `--font-size-1..4`, `--line-height`
- 圆角：`--radius-sm`, `--radius-md`
- 阴影：`--shadow-1`
- 间距：`--space-1..6`

## 组件与样式规范

### 页面骨架
- 页面最大宽度（例如 1100–1200px）居中，左右留白随屏宽自适应。
- 页面标题与副标题形成明确层级，副标题降低对比度。

### 选择卡片（A/B）
- 卡片为可点击区域：边框 + 轻背景 + 悬停态。
- 选中态：主色描边加强 + 背景微弱染色 + 右上角对勾或 “已选” 徽标。
- 文案层级：A/B 字母标识更醒目，标题与说明分层。

### Mockup 容器
- 每个方案预览使用统一容器：标题条（header）+ 内容区（body）。
- 内容区背景略浅于容器，突出“界面画布”感。

### 顶部导航条（mock-nav）
- 作为系统统一入口的视觉提示：浅色条 + 分隔符 + 小号字。

### 区块（section / label）
- label 左侧加窄色条或小圆点增强秩序感。
- 区块间距统一，避免局部用大量内联 style 控制。

### 按钮（mock-button）
- 统一高度、圆角、边框与主色 hover。
- 主次按钮：当前原型可统一为次按钮风格，避免过多蓝色块。

### 占位块（placeholder）
- 采用卡片式列表行：轻背景、1px 边框、内边距统一。
- 文本等宽对齐不强求，但保持行高一致，适合快速扫读。

## 响应式与可访问性

响应式：
- 宽屏：维持方案 A 的左右分栏比例。
- 窄屏：左右分栏改为上下堆叠；按钮与快捷入口自动换行。

可访问性：
- 文字与背景对比度保持可读。
- 点击区域最小尺寸与 hover/focus 态清晰。

## 交互行为

- A/B 卡片点击：仅影响选中态样式（无需弹窗），可在页面上显示“当前已选：A/B”状态文案（可选）。
- 皮肤切换：即时生效并保持选中态（可选地写入 `localStorage`，便于刷新保持）。

## 结构整理要求

- 页面应保持合法 HTML 结构：所有主要内容位于 `body` 内。
- 尽量移除内联样式 `style="..."`，转为 class，以保证风格统一与可维护。

## 验收标准

- 页面不再出现乱码（明确 UTF-8 编码）。
- 页面风格统一，符合“政务/国企蓝”方向，且信息密度适中。
- 选择卡片与 mockup 容器、按钮、占位块的视觉语言一致（圆角/边框/阴影/间距统一）。
- 可在两套皮肤间一键切换，且不破坏布局。
- 在常见屏宽下布局合理（宽屏左右分栏、窄屏可读）。
