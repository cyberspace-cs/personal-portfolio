# 审批工单工作台与智能体 MVP 设计

## 目标

构建一个与现有仓库完全独立的新工程 `audit-workbench`，用于承载审批/工单工作台与对话式智能体能力。

本项目的第一阶段目标是：
- 提供一个适合审计/审批场景的工作台首页，核心信息架构为“顶部语义框 + 可点击概览卡片 + 工单聚合列表”。
- 支持“待我处理 / 我发起 / 我关注 / 同步健康”等概览卡片作为主入口，用户点击卡片即可查看对应列表，无需重复的快捷按钮区。
- 提供一个对话式智能体，能够回答工单进度、审批节点、阻塞原因、下一步操作等问题，并以卡片形式返回关键进度信息。
- 提供真实后端实现，技术栈固定为 `FastAPI + SQLite`，前端为 `React + Vite + Tailwind`。

## 非目标

- 第一版不接入真实企业认证、SSO、权限中心或现有审批系统。
- 第一版不依赖外部大模型服务作为唯一智能体核心能力。
- 第一版不做复杂工作流编排引擎，只实现可演示、可扩展的审批工单流转与查询能力。

## 总体方案

采用前后端分离架构：
- 前端：`React + Vite + Tailwind`
- 后端：`FastAPI`
- 数据库：`SQLite`
- 实时更新：`SSE`（Server-Sent Events）

系统拆分为四个核心部分：
- 工作台前端：展示概览卡片、工单列表、详情、智能体面板
- API 服务：提供统计、列表、详情、审批动作、智能体消息等接口
- 数据存储：保存工单、审批步骤、动态流、关注关系等
- 智能体层：接收自然语言问题，查询业务数据后生成文本答案与进度卡片

## 页面与交互设计

### 1. 工作台首页

页面采用“方案 A”思路，但进一步收敛为更符合业务操作的结构：
- 顶部区域：
  - 页面标题
  - 全局语义输入框
  - 智能体入口提示
- 中部主体：
  - 左侧：概览卡片区
  - 右侧：工单列表区
- 详情展示：
  - 工单详情抽屉或侧栏
- 智能体：
  - 页面右下角浮动按钮或固定侧边面板

### 2. 概览卡片

概览卡片包括：
- 待我处理
- 我发起
- 我关注
- 系统同步健康

交互约束：
- 概览卡片本身就是入口
- 点击 `待我处理` 卡片，右侧工单列表切换为“待我处理”
- 点击 `我发起` 卡片，右侧工单列表切换为“我发起”
- 点击 `我关注` 卡片，右侧工单列表切换为“我关注”
- `系统同步健康` 卡片展示系统同步状态与异常统计，不作为主要列表筛选

结论：
- 删除或不实现“查待办 / 查我发起 / 查我关注”这类重复快捷入口
- 保留顶部语义输入与列表筛选，减少重复导航

### 3. 工单列表

右侧主列表默认显示：
- 首次进入页面时默认显示“待我处理”

列表展示字段：
- 工单编号
- 工单标题
- 当前审批节点
- 当前状态
- 更新时间
- 紧急程度

列表能力：
- 按概览卡片切换视图
- 支持状态筛选
- 支持关键字搜索
- 点击行查看工单详情

### 4. 工单详情

详情区域展示：
- 基础信息
- 审批链路
- 当前节点
- 历史操作记录
- 阻塞原因
- 推荐下一步动作

审批链路以时间线或步骤条展示：
- 已通过
- 待处理
- 已退回
- 已拒绝

### 5. 智能体面板

智能体定位：
- 对审批工单透明化说明
- 对当前工单给出实时进度说明
- 对用户操作提供步骤指导

典型问题：
- “这张单现在到哪一步了？”
- “为什么卡住了？”
- “下一步该谁处理？”
- “我应该怎么操作？”

智能体输出格式：
- 文本回答
- 进度卡片数组

卡片字段第一优先包含：
- 当前节点
- 下一节点
- 当前状态
- 阻塞原因
- 推荐操作步骤

可选字段：
- SLA
- 最近更新时间
- 责任人

## 前端视觉设计

视觉方向：
- 政务/国企蓝
- 信息密度适中
- 低装饰、高可读性、强调秩序

设计原则：
- 卡片承担信息与导航双角色
- 列表区保持高可扫读性
- 智能体卡片和工单卡片视觉上属于同一设计语言

设计令牌建议：
- 主色：政务蓝
- 辅色：灰蓝、浅灰背景
- 文本层级：标题、正文、辅助信息
- 边框与阴影：轻边框、弱阴影
- 圆角与间距：适中，不做过度圆润

布局要求：
- 左侧概览区宽度固定，右侧列表区自适应
- 窄屏下概览与列表上下堆叠
- 智能体面板在窄屏下切换为抽屉

## 后端设计

### 1. 技术选型

- Web 框架：FastAPI
- 数据库：SQLite
- ORM：SQLAlchemy
- 数据校验：Pydantic
- 实时推送：SSE

理由：
- FastAPI 适合快速构建结构清晰的 API
- SQLite 适合独立仓库 MVP，部署门槛低
- SSE 足够满足“实时进度更新”场景，复杂度低于 WebSocket

## API 设计

### 概览与列表

- `GET /api/overview`
  - 返回待我处理、我发起、我关注、同步健康统计

- `GET /api/tickets`
  - 查询参数：
    - `view=todo|initiated|watching`
    - `keyword`
    - `status`
  - 返回工单列表

### 工单详情与动作

- `GET /api/tickets/{ticket_id}`
  - 返回基础信息、审批链路、动态流、推荐动作

- `POST /api/tickets/{ticket_id}/approve`
  - 提交审批通过

- `POST /api/tickets/{ticket_id}/reject`
  - 提交驳回

### 智能体接口

- `POST /api/assistant/messages`
  - 请求：
    - 用户问题
    - 上下文工单 ID（可选）
  - 响应：
    - `text`
    - `cards`
    - `suggestions`

示例响应结构：

```json
{
  "text": "当前工单正在组长审批节点，尚未超时。若你需要继续推进，请先补充退回说明中的附件材料。",
  "cards": [
    {
      "type": "ticket_progress",
      "ticketCode": "WK-20260629-001",
      "currentStep": "组长审批",
      "nextStep": "部门负责人审批",
      "status": "pending",
      "blockerReason": "缺少附件材料",
      "recommendedActions": [
        "补充附件材料",
        "重新提交审批"
      ]
    }
  ],
  "suggestions": [
    "查看审批链路",
    "查看退回原因",
    "如何补交材料"
  ]
}
```

### 实时事件

- `GET /api/events`
  - 使用 SSE 推送以下事件：
    - 工单状态变化
    - 审批步骤变化
    - 动态流新增
    - 同步健康变化

## 智能体设计

第一版智能体不以外部大模型为必需依赖，而是采用“可解释规则层 + 数据查询层”的实现方式。

处理流程：
1. 接收用户问题
2. 识别意图
   - 查询当前进度
   - 查询阻塞原因
   - 查询下一步动作
   - 查询流程说明
3. 查询数据库
4. 拼装标准文本回答
5. 返回进度卡片

这样设计的原因：
- 结果稳定、便于测试
- 不依赖密钥与外部模型
- 后续可以在服务层外再接入 LLM 适配器，不推翻 API 结构

## 前后端数据流

典型场景：点击“待我处理”

1. 前端点击概览卡片 `待我处理`
2. 前端调用 `GET /api/tickets?view=todo`
3. 后端返回列表
4. 前端刷新右侧列表

典型场景：用户询问工单进度

1. 用户在智能体面板输入问题
2. 前端调用 `POST /api/assistant/messages`
3. 后端解析问题并查询工单及审批步骤
4. 后端返回文本 + 进度卡片
5. 前端在聊天区渲染回答与卡片

典型场景：审批状态变化

1. 某工单被审批通过或驳回
2. 后端写入审批步骤与活动流
3. SSE 推送事件
4. 前端更新概览统计、列表项状态与详情视图

## MVP 范围

第一版必须完成：
- 独立前后端工程初始化
- 概览卡片驱动右侧列表切换
- 工单列表与详情
- FastAPI + SQLite 基础 CRUD
- SSE 实时事件流
- 智能体问答接口
- 智能体卡片化进度返回
- 政务/国企蓝风格前端布局

第一版可暂缓：
- 登录鉴权
- 多租户
- 文件上传
- 外部审批系统同步
- 真正的大模型推理

## 错误处理

后端：
- 未找到工单时返回 404
- 非法审批动作返回 400
- SSE 推送异常时记录日志并允许前端重连

前端：
- 接口失败展示空状态或错误提示
- SSE 断开后自动重连
- 智能体无法理解问题时给出可选建议问题

## 测试策略

后端：
- API 基础单元测试
- 服务层测试：进度计算、阻塞原因、智能体返回结构

前端：
- 关键组件渲染测试
- 概览卡片切换列表的交互测试
- 智能体卡片渲染测试

手工验证重点：
- 点击卡片是否立即切换列表
- 工单状态变化后前端是否更新
- 智能体回答是否能准确显示当前节点、下一节点和操作建议

## 验收标准

- 项目是一个独立新工程，不依赖原仓库结构
- 用户进入首页时默认看到“待我处理”列表
- 概览卡片直接承担导航功能，不需要重复快捷按钮区
- 前端整体视觉符合“政务/国企蓝 + 适中密度”
- 后端提供真实 API 与 SQLite 持久化
- 智能体可以针对工单返回文本说明与进度卡片
- 工单进度变化可通过 SSE 近实时反映到页面
