# 刷题教练平台 · AI 优化最佳实践提示词库

> 本库沉淀自 **WorkBuddy / CodeBuddy 对话历史中的迭代提示词**，适配 TRAE Work 等 AI 编程助手，
> 用于持续打磨「专属刷题教练」平台（多源题库聚合 × 智能推荐 × 模拟考场）。
>
> 用法：复制对应维度的模板，把 `{占位符}` 换成你的具体内容；遵循「小步快跑」，每轮只改一个点，跑通再继续。

---

## 0. 总原则（贯穿所有维度）

1. **结构化指令**：角色 + 上下文 + 约束 + 交付物 + 自检清单，五段缺一不可。
2. **小步快跑**：每轮只改一个点，跑通再继续，避免一次堆十个改动导致无法定位问题。
3. **默认决策先行**：让 AI 先给「默认决策 + 理由」并标注「推荐」，你用文字纠偏即可（不要依赖弹窗确认）。
4. **闭环可验证**：每次改动后要求 AI 跑自检命令（语法/构建/预览），并给出「改了什么 / 为什么 / 下一步」三行总结。
5. **版本可追溯**：把每次迭代写进「完整版本历史」，打版本号 + 日期 + `新功能/优化/修复/待修复` 标签。

> 真实迭代案例（来自本项目对话历史）：
> - **视觉统一**：初版「借鉴 AIOPS/MonkeyCode/nanobot 改 6 个项目」→ 迭代「先建统一设计系统 `_shared.css`/`_shared.js` 再逐页重写」→ 再迭代「学 dianaagent.top 的版本历史样式补『历程』」。
> - **离线安全**：发现 ES module 在 `file://` 下触发 CORS 报错 → 改为 IIFE 全局挂载，去掉一切外部 CDN 依赖。
> - **规则降级**：无 API Key 也能完整演示，配置 Key 后自动升级为真实大模型生成。

## 1. 产品设计

**核心目标**：把模糊想法收敛成可落地的产品定位与差异化。

### 提示词模板

**v1 — 定位收敛**
```
你是资深 AI 产品负责人。请用一句话说清 {产品名} 的定位、目标用户、核心差异化。
输出：
① 电梯演讲（≤30 字）
② 用户画像（3 类，含场景与痛点）
③ 最该做对的 3 个核心场景
```

**v2 — 迭代（参考竞品）**
```
在 v1 基础上，参考 {竞品A} 的 {优点} 与 {竞品B} 的 {优点}，但规避其 {短板}。
输出 PRD 大纲：背景 / 目标 / 范围 / 非目标 / 核心指标（北极星 + 2 个护栏指标）。
```

### 刷题教练落地
- **定位**：多源题库聚合 × 智能推荐 × 模拟考场的「备考操作系统」。
- **差异化**：打通 考研帮 / 粉笔行测 / LeetCode / 牛客 / 中公 的数据孤岛，统一管理刷题数据。
- **北极星指标**：周活跃刷题时长；护栏指标：错题本归集准确率、推荐点击率。

## 2. 需求调研

**核心目标**：把「我想要 XX」变成可验证、可排期的需求。

### 提示词模板

**用户故事拆解**
```
把『{模糊需求}』拆成用户故事：
作为 {角色}，我希望 {能力}，以便 {价值}。
每条标注 MoSCoW 优先级（Must/Should/Could/Won't）与可验证的验收标准（Given/When/Then）。
```

**快速验证**
```
设计一份面向 {目标用户} 的访谈提纲（10 题），覆盖 {痛点 / 现有方案 / 付费意愿}，
并给出如何用最少样本（≤5 人）快速验证核心假设的方法。
```

### 刷题教练落地
- 三线用户（考研 / 考公 / 大厂面试）的痛点访谈与优先级排序。
- 验收示例：`Given` 用户答错某知识点题，`When` 进入错题本，`Then` 该知识点权重 +1 且下次推荐概率提升。

## 3. 技术选型

**核心目标**：在真实约束下做可辩护的技术决策，预留回滚方案。

### 提示词模板
```
在约束 {无 API Key 可演示 / 离线可用 / file:// 兼容 / 国内访问顺畅 / 单文件可部署} 下，
对比 {方案A} 与 {方案B}。
输出：
① 决策表（维度｜权重｜A｜B｜结论）
② 回滚方案
③ 一份最小验证 PoC 步骤（≤5 步）
```

### 刷题教练落地
- **前端**：原生 HTML/CSS/JS + 统一 `_shared.css`（离线安全，无 CDN / ES module 依赖）。
- **存储**：`localStorage` 持久化（错题 / 打卡 / 画像）优先，后端按需。
- **图表**：Chart.js（轻量、无构建步骤）。
- **决策记录**：见 `Audit-AIOPS/docs/agent-rd-path.md` 的选型推演范式。

## 4. Agent / 大模型做助手迭代

**核心目标**：把大模型当协作者——规则降级优先、可编排、可观测、可溯源。

### 关键模式（来自对话迭代）
- **规则降级优先**：无 Key 时用确定性规则跑通全流程，配置 Key 后升级为真实生成。
- **可编排可视化**：把 Agent 的 ReAct 步骤做成可见的流水线动画（数据校验→训练→监控→推理）。
- **引用可溯源**：RAG 答案必须能给出来源并定位原文（检索质量看引用能否点回去）。
- **失败有兜底**：意图识别不到时走兜底通道，不静默失败。

### 提示词模板

**v1 — 骨架**
```
帮我用 {框架} 实现 {功能}，先给一个可运行的最小骨架。
```

**v2 — 规则降级**
```
改为规则降级版：无 Key 也能完整演示；预留接口，配置 Key 后自动切换为真实模型生成。
```

**v3 — 可观测可溯源**
```
增加 ReAct 编排可视化 + 引用溯源标记 + 失败兜底话术；把每一步的中间结果打印到可观察面板。
```

### 刷题教练落地
- **AI 对话答疑**：题目解析、知识点追问、个性化辅导。
- **智能组卷**：按知识点分布与历年真题 AI 生成高质量模拟卷。
- **个性化推荐**：基于错题动态排序，优先强化最薄弱知识点。

## 5. 前后端开发

**核心目标**：产出可维护、可演示、低返工的代码。

### 提示词模板
```
按以下约束实现 {模块}：
① 组件 / 函数单一职责
② 离线安全（不使用 ES module / 不依赖外部 CDN）
③ 先跑通主链路再美化
④ 改动后用 {自检命令} 验证（语法 / 构建）
⑤ 给出自检清单（你如何确认没破坏现有交互）
```

```
重构 {文件}：抽取公共 {设计系统 / 工具函数} 到 {_shared.css / _shared.js}，
保持各页风格一致，不要破坏现有交互与动画。
```

### 刷题教练落地
- **统一设计系统**：蓝白科技感、玻璃拟态、紫蓝渐变（参考 `public/demos/_shared.css`）。
- **数据中心**：趋势图 / 雷达图 / 饼图多维度呈现知识点掌握度。
- **错题本**：跨平台归集 + `localStorage`/`SQLite` 落盘，重启不丢。

## 6. 协同沟通

**核心目标**：人机协同不返工，决策可追溯。

### 提示词模板
```
请按这个范式回复：
① 先给默认决策并标注「推荐」
② 列出 2-3 个选项与各自取舍
③ 用文字让我纠偏，而非弹窗确认
④ 结尾用 3 行总结：改了什么 / 为什么 / 下一步
```

```
每次改动后，把关键决策追加到 {版本历史}，
记录：版本号、日期、以及 新功能 / 优化 / 修复 / 待修复 标签。
```

### 刷题教练落地
- 用「完整版本历史 / 创作历程」记录每次迭代（v1.0 → v2.0 …）。
- 与 TRAE Work 协作时，每轮只给一个明确指令，避免一次性堆砌导致无法定位问题。
